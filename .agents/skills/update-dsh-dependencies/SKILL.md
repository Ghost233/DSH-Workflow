# 更新 DSH 依赖并验证兼容性

在源码 checkout 中执行。只检查更新时，执行第 1 节并按第 4 节报告，可只读核对兼容声明；不执行更新或候选构建。用户要求更新时，再执行完整流程。讨论或编辑技能不构成升级授权。

## 1. 记录当前版本并检查上游

以 Git 根目录为工作位置，先读 [AGENTS.md](../../../AGENTS.md)、[领域文档](../../../docs/agents/domain.md)和相关 ADR。记录分支、完整 HEAD、工作区改动和每个子模块的 HEAD。保留已有修改；后续只编辑本次更新负责的内容。GitHub 操作按[账号约定](../../../docs/agents/issue-tracker.md)核验 Ghost233，Git 远端操作另核验实际凭据。

逐项检查以下来源，记录原版本、最新候选、完整提交、来源链接及检查时间：

- `.gitmodules` 中的全部子模块，以及 `dsh-runtime.json` 指定的 DSH 运行时。
- `project-plugins.json` 中的全部插件，包括未标记 `startup: true` 的条目。
- Matt 派生版、Browser Harness 和 `vendor/*.upstream.json` 记录的技能来源。自研插件按本仓源码验证，不套用同名第三方包。

沿用每个组件已采用的渠道：发布标签选择同渠道最新发布；跟踪主线的基准选择已核实的分支提交。用户明确指定渠道时按其要求执行。npm `latest` 可能比已采用的 `next` 更旧；同一版本号也可能有不同提交，均须核对。Git 来源继续查询原仓库，不切换到同名 npm 包。

完成标准：范围内每项都有更新结论；查询失败写为“未验证”，不记成“无新版”。

## 2. 更新固定输入

更新子模块前确认其源码干净，只切换到已核实的精确提交，保持上游源码原样。DSH 更新时同步 `dsh-runtime.json`、启动器依赖及生成锁文件，并重建受影响的生产包与 Desktop；审计适配摘要、锚点及版本约束，不绕过固定输入校验。

Matt 更新必须先读 [派生版说明](../../../matt-skills-panel-plugin/README.md)，使用其 `upstream:check -- --prepare` 生成三方提案。审查冲突、自动合并和上游删除，保留项目定制。通过构建与派生版测试后，更新基准、本地版本和包管理器生成的锁文件。其他第三方插件不改源码。

插件更新保持原安装来源、清单范围和启动选择。更新 `project-plugins.lock.json` 时，遵循仓库要求使用 Apple container：容器内执行真实 `npm view 包名@精确版本或标签 --json --registry 清单指定源`，Git 包元数据取固定官方提交。由脚本生成锁文件并核对清单 SHA-256；查询或生成失败时保留原锁文件。只在隔离的准备目录下载和装配依赖，运行中的 profile 不执行在线换包。

Browser Harness 推进后核对所选技能文件、版本、提交和 SHA-256，保持既有交付范围。验证工具需调用 `browser-harness` 时，按当前 Agent 的唯一 `BU_NAME` 规则复用命名空间。

完成标准：清单、锁文件、子模块提交和受影响产物一致；所有固定输入可从已记录来源复核。

## 3. 验证兼容性

先核对 DSH 版本范围、peer dependencies、客户端 inject、宿主 API、插件入口及 bundle patch。声明满足只记“声明兼容”，不据此断言已能运行。

读取当前测试入口和 CI 配置，按最终候选输入完成本地检查：

- 运行完整 `node scripts/run-project-tests.mjs`；保留清单、包体、启动结果、profile 迁移和真实 Host 的业务断言。
- Matt 有变化时，完成其构建、全部派生版测试及维护中的类型检查配置。DSH 或 Desktop 接入有变化时，额外验证精确上游输入、篡改拒绝和重复装配。
- 构建隔离候选 App，重新验证所有 `startup: true` 插件的本体、生产依赖、来源和文件摘要。使用候选资源完成完整 Flutter 验收；随包 Node 使用无空格路径，Web 测试使用临时端口。
- 在独立 HOME/profile 中验证全新安装、旧 profile 升级、应用目录迁移和用户主动停用。真实 Host 须报告实际版本、解析路径和加载状态；界面插件须实际打开对应入口。保留用户停用选择，不启动模型任务或操作现有服务来凑验收。

复用 [deploy-release 的本地验收约定](../deploy-release/SKILL.md#插件随包交付)确定候选资源、完整 Flutter 命令及交付要求；本节引用不启动发布。已有构建输出保留，使用未占用的候选输出位置，不为测试擅自递增应用版本。

不兼容项记录具体声明、原始错误和整体启动影响，保留此前固定版本；继续处理可独立验证的其他组件。遵循仓库维护边界，不修补第三方、不删减验收范围、不放宽超时或伪造通过。无法执行或缺少证据的检查保持“未验证”。记录命令、源码版本、真实退出码和清理结果；输入变化后重建对应产物，并复验受影响项目。

完成标准：最终固定组合通过必需检查；兼容结论区分声明、实际加载、界面可用及未验证部分。测试资源已退出，清理异常单独记录。

## 4. 交付结果

逐项列出原版本、所查最新版本、本次采用版本/提交、兼容结论和证据。明确无新版、查询失败、因不兼容保留旧版的项目，并汇总本地门禁、未验项和工作区状态。

提交、推送、发布或切换服务沿用用户当前的明确授权。用户同时要求正式发布时，再按 [deploy-release](../deploy-release/SKILL.md)执行；已有版本号和动作授权继续有效。只要求更新检查时，不自行创建发布标签、替换本机 App 或重启服务。
