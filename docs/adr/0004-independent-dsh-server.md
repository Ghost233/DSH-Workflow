# 由独立 DSH 服务端承载桌面端和 Web 的共享业务

用户选择让 DSH 服务端独立运行，桌面客户端和 Web 访问同一个实例。客户端只建立和关闭连接；关闭客户端不停止服务端，也不以打开客户端作为启动服务端的前提。

采用自研服务端插件、项目运行编排和最小桌面接入适配的组合，继续使用现有 DSH 桌面客户端。普通 DSH 插件在 Host 启动后加载，无法独自替换 Electron 创建 Host 的行为，因此需要桌面接入适配。服务端的启动和停止由项目运行编排负责，插件不承担启动自身所在进程的职责。

首版服务端运行在当前 Mac 上，本机桌面端、浏览器和已有局域网 Web 入口共享该实例。停止或重启服务前检查运行中的代理、后台任务和待处理工作；有未完成工作时先展示并取得明确确认。

服务由启动器明确启停。开启登录启动后自动启动服务，不强制打开桌面窗口；退出启动器后，服务和 Web 入口继续运行。服务异常退出后保持停止，通过系统通知提醒用户检查，等待用户手动启动。

保留桌面内嵌用量和充值页，专用凭据只通过受限的本机连接传给 Electron 主进程。同机目录选择、拖拽和 Office 能力继续保留。

DSH 服务和 Web 入口分别控制。停止 Web 仅关闭浏览器访问，桌面端与业务继续运行；停止 DSH 服务后，保留的 Web 入口显示服务不可用。

DSH、桌面适配和插件由本仓库统一固定版本并发布，应用只检查本仓库的 DMG。运行端不直接更新到上游原版，避免绕过适配和共享实例约束。服务重载和停机仍须遵守任务检查规则。

这项决定替代旧启动器规格中“由 Desktop 持有业务后端”和“缺少后端就打开官方桌面端”的行为。用户已授权本方案必需的桌面端修改，其余 DSH 上游和第三方插件仍遵循现有维护边界。用户于 2026-10-17 确认整体设计并授权实施，具体边界见[正式规格](../specs/independent-dsh-server/spec.md)和[设计访谈](../analysis/2026-10-17-independent-dsh-server/design-interview.md)。本 ADR 不表示实现已完成。
