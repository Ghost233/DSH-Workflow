# 用统一 JEV 中心按名称调用多套引擎配置

JEV 引擎配置由独立的自研 JEV 中心管理，消费插件指定 model 名字，中心选择相应配置发起 System One 判断请求并返回结果。用户要求多套配置可以同时启用，因此不采用全局唯一“当前配置”，也不让各消费插件分别维护 URL、凭据与上游调用实现。

调用模型名默认沿用上游模型名，也允许自定义；请求仍携带配置中的上游模型标识。请求发出后保持原配置，修改影响后续请求；配置不可用或请求失败返回明确错误，不静默切换到另一套配置。

已启用配置的调用模型名必须唯一。消费插件保存自己所选择的调用名称；停用或删除引擎配置不阻止操作，也不自动删除DSH凭据，后续调用明确返回不可用。监控测试版本为主、子代理共用一个调用名称，语义检测不可用时其确定性检测继续。

这个决定固定配置归属和插件间的调用关系，后续功能可复用同一入口；它不授权监控插件自动中止、重试或替主代理切换模型。完整设计、测试参数和可观测性已在[设计访谈](../analysis/2026-10-07-knoxcoder-jev/jev-config-design.md)中由用户确认。用户随后调用 spec-delivery 并要求开新分支，恢复本规格实施；当前状态见[交付记录](../specs/jev-center-agent-monitor/delivery.md)。
