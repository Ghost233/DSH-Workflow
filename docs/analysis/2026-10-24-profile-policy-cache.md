# 0.4.3：已有 profile 的策略缓存修复

用户在 0.4.2 报告前端无法启动，提示 `ui-entry-customization` 等待 `pluginNavigation`。安装包中的停用规则已存在，但已有 profile 的项目生成层仍没有对应停用条目。新隔离 profile 的验收没有覆盖这一升级场景。

`prepareDesktopProfile()` 的缓存身份原先只包含固定集成版本、安装路径、DSH 版本及部分配置。应用原地升级后，这些值可能保持相同；函数提前返回，错误沿用旧的生成覆盖层。现在将实际共享的 `packageMutationModules` 纳入身份，旧记录缺少该字段或策略发生变化时，都会重新生成项目覆盖层。

回归测试模拟相同安装路径下的旧 stamp 和缺失规则，先确认原实现失败，再验证新实现重建规则。同时检查用户的 package.json、cordis.patch.yml、cordis.yml 字节不变，以及重复准备的幂等性。

已经运行的旧管理进程不会随磁盘文件更新而替换内存代码。该缓存修复在新版代码准备 profile 时生效；旧进程的恢复仍须遵循既有任务检查和安全启停流程。本次发布不新增自动中断或回收运行中服务的行为，也不操作当前已恢复的服务。

本机此前已在确认没有待执行工作后完成单独恢复：备份生成记录，正常结束旧管理器，由已安装启动器启动当前代码，重建覆盖层，再确认真实桌面正常打开。用户配置逐字节校验通过。该恢复不等同于把未发布源码写入已安装 App。

本次应用版本为 0.4.3。DSH、第三方插件、Matt 派生版及 Browser Harness 固定基准均沿用 0.4.2，不在补丁发布中追踪新上游。正式发布使用当前 main、附注 tag macos-v0.4.3 和标准 Actions 管线；本地验收与最终发布证据保留在 .build/release-0.4.3/。
