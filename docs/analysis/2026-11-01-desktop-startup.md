# 2026-11-01 桌面端启动竞态

0.5.0 发布后，用户授权关闭已安装的 0.4.7，并对 0.5.0 候选进行隔离窗口测试。冷启动时桌面窗口正常显示，观察到同一进程持续约 15 秒。保存启动偏好后的重启验收未通过：现有测试仍假设 Desktop 拥有 Host，并且部分设置需要滚动才能访问。详情及测试数据隔离问题见 [2026-10-31 依赖更新记录](2026-10-31-dependency-update.md)。

## 已修复的竞态

桌面端连接共享服务时，如果服务管理器已经启动但仍在准备 Host，管理器会返回暂不可用；旧客户端立即向用户报错。0.5.1 对已确认处于 `starting` 的服务进行有界等待，最长等待 45 秒。对于 macOS 恢复启动、没有启动器环境变量的 Desktop，管理器尚未出现或服务暂时停止时再给予最多 5 秒等待；手动由启动器打开的 Desktop 遇到已停止服务仍立即报错。服务失败、版本不兼容或控制 socket 不安全时保留相应错误；客户端不启动或重启服务。连接检查与状态检查之间服务恰好就绪时，客户端再尝试一次连接。

回归使用了本地 Unix socket 模拟状态变化，并在私有 HOME 与 profile 中启动真实 DSH Host：在服务实际处于 `starting` 时发起桌面连接，经过多次检查接入同一个 Host 实例。实际窗口验收分别覆盖 Host 正在启动和 Desktop 先于服务管理器启动两种顺序；后一种顺序中，管理器在 Desktop 启动约 2.5 秒后建立，正常欢迎窗口出现，同一桌面进程稳定运行至少 10 秒。测试未发送模型任务，桌面和 Host 均正常停止。

## 验证边界

该修复覆盖已证实的“桌面连接早于服务就绪”竞态，也覆盖 macOS 恢复窗口早于管理 socket 建立的短暂时序。尚未在真实电脑重启后复现用户报告的反复退出，也不能据此断言这是该问题的唯一原因。

## 0.5.2 高负载启动检查

后续隔离验收时，真实 Host 已开始提供 Web，但在系统高负载下，启动阶段的一次两秒健康检查超时，服务管理器随即停止 Host。另一轮真实 Host 检查也复现了同类超时；这些失败及清理记录保留在本地证据目录。

0.5.2 在原有 30 秒 Host 启动预算内重试健康检查的超时，每次检查仍使用不超过两秒的时限。只有有效的实际只读清单才能确认就绪；清单不合法、受管策略错误或 Host 已退出时不按超时重试。该改动没有延长启动预算，也没有放宽就绪断言。

组合验收先在隔离环境启动 0.5.2 Desktop，再启动真实服务管理器，并让第一次健康请求按原时限超时。Host 随后通过真实健康检查，桌面显示正常欢迎窗口且同一进程稳定至少 10 秒；通过应用菜单退出的退出码为 0，Host 经任务检查后正常停止。
