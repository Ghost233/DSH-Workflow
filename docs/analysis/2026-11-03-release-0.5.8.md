# Ghost DSH Station 0.5.8 发布验收

本次版本由用户指定为 0.5.8，从 `985a8912b7288bc8e8b6269e810967baddc08728` 基线发布。包含窗口与进程生命周期改造、已完成的依赖更新，以及旧插件残留处理。发布不替换本机 App，不切换正式服务。

## 行为变化

Station 和 DSH 桌面客户端有窗口时显示 Dock 图标并支持 Command-Tab；关闭全部窗口后收回菜单栏，最小化仍保留 Dock 图标。Station 的红色关闭按钮隐藏窗口，菜单退出或 Command-Q 才检查未完成工作并停止全部受管服务。取消后保留服务，清理失败时保留窗口并显示原因。

后台 DSH 使用随包独立 Node，Electron 仅承载桌面客户端。退出时统一停止日常 DSH、Web 和各 Superagent，按启动记录、PID、用户、启动时间和命令身份回收管理器及遗留后代，包含 MCP 和辅助进程；不按进程名称批量结束外部 Node。

依赖版本、官方来源和容器元数据生成过程见 [依赖更新记录](2026-11-03-dependency-update.md)。本轮更新上下文洞察 0.80.2、费用 1.9.50、通知 0.4.8、模型提供商 0.4.3、飞书 CLI 1.0.98，以及 Browser Harness 固定提交；DSH 保持 rc.5，Matt 保持已发布 beta.33。容器维护文本统一使用 OrbStack Docker 与标准 Docker Compose。

## 旧 profile 与退役插件

`billion-context` 已于 0.4.9 从交付清单移除，当前 `dsh-context` 是独立的上下文洞察插件。旧用户 profile 中的依赖和 bundle 声明仍可能遗留。项目启动装配现在明确停用退役包的宿主和预设入口，共享给 Superagent 时排除该包；缓存以实际启动覆盖层摘要判断是否需要刷新，不修改上游源码。

本机审计确认，正式管理进程仍以 `~/.dsh` 为日常配置来源。Station 目录下较早的 `home` 快照不能作为“已完成独立目录迁移”的证据。2026-10-20 的部署记录证明旧版 Station 曾接管已存在的 billion-context 安装，但不能据此断言首次安装来源。

用户选择继续使用当前目录，并明确授权清理 billion-context，随后授权清理 dsh-our-free-model。两者均为当前交付清单之外、指向缺失包目录的失效链接。操作前在 Station 私有 `cleanup-backups/legacy-20261103-CpAygo/` 备份，再清理 desktop 的依赖、bundle、对应旧覆盖项与锁记录，以及历史插件清单中的相关项，并移动两个断链。修改后的 YAML 和 JSON 与仅移除目标项的预期结构逐项比对；其他配置值保持不变，没有运行包管理器、删除凭据或重启服务。

原始 Matt 面板 1.7.39、旧 Web profile、既有备份及较早的 Station home 保留。它们包含旧文件或用户数据，未按“未出现在交付清单”这一条件直接删除。
