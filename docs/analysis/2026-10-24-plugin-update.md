## 构建与验收

插件发布元数据通过 Apple container 内的 `npm view` 查询，再由脚本生成锁文件并核对清单摘要。首次查询因容器 DNS 失败退出，原锁文件保持不动；后续临时容器使用宿主刚解析的官方域名地址，真实 HTTPS 校验和查询均通过，没有改动宿主 DNS。

发布前的实际页面验收发现，rc.3 新增的 `ui-entry-customization` 仍依赖已按只读策略停用的插件管理导航。项目将这个入口纳入同一启动覆盖策略，不改上游、不恢复安装渠道。关闭该菜单时，上游会话视图直接显示全部标签；版本与来源页仍沿用现有入口。

Desktop 主文件的审计摘要同步到 rc.3。对照源码与编译结果，唯一变化是客户端版本字符串；精确摘要、适配锚点、成员校验和幂等要求均保留，回归增加了篡改输入拒绝检查。

启动插件验收的准备阶段原需逐文件复制约 2.8 万个成员，耗时约 53 秒。测试夹具改用 macOS 独立写时复制，并在加入自研验收包前核验完整原封存数据。原 75 秒期限、全部真实插件和业务断言保持不变；定点验收约 45 秒通过。

DSH rc.3 的开发钩子安装器拒绝本地 submodule 的 `core.worktree` 配置。项目生产安装采用与 Actions 一致的 `CI=true`，跳过开发钩子安装；冻结依赖、生产编译、签名及包体校验要求保留，DSH 源码保持原样。

最终候选已构建并签名，隔离页面已正常启动。九个清单插件均报告 `loaded`，实际版本和路径来自候选包；Matt 的宿主与工具、Browser Harness 管理插件均为活动状态。Browser Harness 的实际 DSH Shell 查询返回 `/opt/homebrew/bin/browser-harness`、0.1.13。该查询不代表浏览器连接或模型推理已经验证。
