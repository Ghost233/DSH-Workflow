## 已确定的设计树

```text
目标：前置思考，Owner 负责模块，小模型准确执行，减少用户过程参与
├─ 用户交互 [U4/U7]
│  ├─ 需求讨论、总结、Spec、Ticket 均由主线程统一处理
│  ├─ 技术问题由主线程结合 Owner 证据处理
│  └─ 产品取舍、需求变化及真实外部权限需要用户决定
├─ 产物顺序 [U3/U5/U8]
│  ├─ Spec：需求、合同、AC
│  ├─ Ticket：工作切片、交付要求和逻辑依赖
│  └─ 执行 DAG：Owner 执行包、运行依赖与状态
├─ 模块责任 [U1/U2]
│  ├─ Owner 保存历史原因、版本与当前状态
│  ├─ 公共 Owner 独立判断请求和消费者影响
│  └─ 业务 Ticket 可跨模块，执行写入按单 Owner 隔离
└─ 自主执行与反馈 [U5/U6/U7]
   ├─ Runner 根据就绪条件、Owner 和执行资源派发
   ├─ 问题返回主线程：继续、局部改图、改任务/技术合同
   ├─ 需求取舍变化才返回用户决定
   └─ 自动验收与技术修复，达到目标交付；无法推进则保留现场并报告
```

当前没有为记录这些已明确方向而必须追问的用户前沿问题。未定的技术取值与集成验证列于规格，不把它们写成用户已经批准的细节。用户后续提出新约束时，从这棵树对应分支修订，不从头访谈。

## 被后续讨论替代的观点

| 早期观点 | 当前决定 | 原因 |

| 每轮实现、测试和反思后进入 awaiting_discussion，用户确认才继续 | 无固定人工轮次门禁；技术问题自主闭环 | U7 明确希望除需求决定外不再参与 |

| Matt 符合要求主要因为每轮停下讨论 | 采用其规格、业务切片、证据与反思方法；不照搬人工轮次节奏 | 用户后续澄清自主执行目标 |
| 一个业务 Ticket 必须只属于一个 Owner | 业务 Ticket 可映射多个单 Owner 执行包 | 同时满足完整行为与严格写入责任 |

## 证据与认识边界

- 历史 GhostNexus 失败链有日志依据：固定命令缺失 → handoff → 审批失效后再派发 → blocked。当前控制决策器已有 handoff 优先路由；不能把历史缺陷与当前状态混为一谈。
- 同一讨论此前运行的定向测试为 25 通过；额外诊断为 2 通过、3 失败，分别暴露自然语言续期、义务遗漏关闭、关键词授权分类问题。原始日志保留在本目录；本次文档工作未重新运行，不算新的全链路验证。
- 没有不同模型的 A/B 实验，不能把模型能力认定为全部根因，也不能承诺换模型即可解决。
- Coinhub/WalletConnect 的旧工作区路径缺失，不能断言那次完整运行已复现。
- 当前仓库有原有未提交修改；代码事实来自磁盘内容。源码指纹见 `source-fingerprints.json`，规格记录哪些部分只是目标设计。
