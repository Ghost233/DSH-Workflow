# 重启后桌面客户端缺少启动器环境

## 结论与证据

0.4.3 的桌面接入层要求进程带有 `DSH_WORKFLOW_DATA_ROOT`。缺少这个变量时，代码直接抛出“请从 DSH 启动器打开桌面客户端”，还未尝试连接已有服务。

用户报告重启电脑后自动启动报错，停止再启动恢复。诊断文件为 `crash-2026-10-24T18-13-50-920Z-host.log`。服务日志显示，Host 在北京时间 2026-10-25 02:12:47.213 已就绪；客户端在 02:13:50.920 因缺少变量失败。因此，这次失败发生在客户端的连接目录检查。

开机恢复客户端且缺少启动器环境，能够解释这次现象。隔离测试已复现同一错误。未采集到系统恢复事件的独立记录，也未实际重启 macOS。启动器的登录项代码注册 `SMAppService.mainApp`；本次未修改系统登录项。

## 修改

`WorkflowDesktopConnection` 优先使用启动器传入的目录。缺少该变量时，使用当前用户的 `Library/Application Support/DSH Workflow`，连接已有管理 socket。后续连接检查使用同一个目录。

连接仍校验 socket 所有者、权限、协议和运行时版本。客户端不创建 Host，不修改用户 profile，不新增轮询，也不自动重启服务。服务未启动或暂不可用时，继续如实报错。

## 验证

基线提交为 `f1fd6eb4b954762b8ab3b30b5c63b5c679fa96cd`。首次执行以下定点测试，退出码为 1，错误与诊断报告一致。修改后同一用例通过。

```sh
node --test --test-name-pattern=macOS-restored macos-launcher/runtime/desktop-client.test.mjs
```

新增回归覆盖缺少启动器环境时连接已有服务、短暂不可用后恢复，以及私有 socket 权限检查。原有用例同时验证显式传入目录仍然优先。

最终验证均以真实退出码 0 验收：

- 完整 Node 测试 308 项通过，包含实际 Host 的项目组合测试。
- 固定上游 Desktop 的打包适配检查通过，包含输入篡改拒绝和重复装配检查。
- 在独立 HOME 中启动真实 Host。旧版客户端模块因缺少环境变量报错；重新装配的模块连接同一 Host，读取当前前端启动清单。
- 关闭客户端后，Host 的 PID、实例标识和就绪状态保持不变。用户 profile 文件内容未变。测试 Host 正常停止，管理进程正常关闭，无测试进程残留。

完整测试的首次沙箱运行出现原生文件监听 `EMFILE`，随后因用户中断未完成，不记为通过。单个原生监听探针在沙箱内失败、沙箱外通过。保持源码、断言和超时不变，在沙箱外依次通过原失败用例、所属模块和完整测试。未调整系统句柄限制。
