# DSH 独立服务设计访谈

本记录保存设计访谈中的决定和代码事实。架构决定见 [ADR-0004](../../adr/0004-independent-dsh-server.md)，领域术语见 [GLOSSARY.md](../../../GLOSSARY.md)。用户已完成整体设计确认，正式范围见[规格](../../specs/independent-dsh-server/spec.md)。

## 已确定的边界

- 采用自研服务端插件、项目运行编排和最小桌面接入适配。
- 服务端独立运行，桌面端和 Web 连接同一个实例。客户端不负责启动或停止服务端。
- 首版运行在当前 Mac 上，覆盖本机桌面端、本机 Web 和已有局域网 Web 访问。跨机器桌面连接不在首版范围内。
- 停止或重启前检查未完成工作。有未完成工作时，先展示工作并取得明确确认。
- 打开启动器时自动启动或复用服务，并保留明确启停操作，不强制打开桌面窗口；退出启动器保留服务和 Web 入口。登录启动沿用现有开关。
- 服务异常退出后保持停止，等待用户手动启动。发送 macOS 系统通知提醒用户检查；独立管理进程承担故障通知，启动器退出后仍须通知。运行编排不额外重发任务，恢复沿用 DSH 行为。
- 保留内嵌用量和充值页，专用凭据只通过受限的本机主进程连接传递。同机目录选择、拖拽和 Office 能力继续保留。
- DSH 服务和 Web 入口分别控制。停止 Web 只关闭浏览器访问，桌面端与业务继续运行；停止 DSH 服务后，保留的 Web 入口显示服务不可用。
- DSH、桌面适配和插件版本由仓库统一固定并发布，运行端不直接更新到上游原版。应用检查更新只检查本仓库的 DMG；组件升级在仓库中完成，并随正式包交付。
- 用户已授权必要的桌面端修改。其余 DSH 上游和第三方插件维持现有维护边界。

## 代码事实

证据基于 DSH `0.2.1-alpha.5`、提交 `1517a4dbca0a2789ff1d41ba439600f8547d23fa`。

- 当前业务 Host 由 Electron 创建。关闭窗口只隐藏，真正退出 Electron 会关闭 Host。参见 [main.ts](../../../deepseek-harness/apps/desktop/src/main.ts) 和 [host-process.ts](../../../deepseek-harness/apps/desktop/src/host-process.ts)。
- 当前 Web supervisor 受启动器父进程和标准输入控制，退出启动器会回收 Web 入口。常驻服务需要改变这一拥有关系。参见 [global-supervisor.mjs](../../../macos-launcher/runtime/global-supervisor.mjs) 和 [launcher_controller.dart](../../../macos-launcher/flutter/lib/launcher_controller.dart)。
- DSH 已有认证、会话通信和重连机制，接入应复用这些机制。Electron 的启动描述和任务检查目前来自私有 IPC，需要补充等价接入。参见 [main.ts](../../../deepseek-harness/apps/desktop/src/main.ts) 和 [desktop-host](../../../deepseek-harness/apps/desktop-host/src/index.ts)。
- 当前桌面构建读取固定上游源码。桌面适配需要由主仓库保存并在构建时装配，避免再次出现只有本地工作区包含修改、CI 未包含修改的情况。参见 [build-desktop-release.mjs](../../../macos-launcher/build-desktop-release.mjs)。
- 现有桌面更新会锁定业务请求并停止 Host。接入独立服务后，需要分离客户端更新和服务端停止的权限。参见 [main.ts](../../../deepseek-harness/apps/desktop/src/main.ts) 和 [update-tasks.ts](../../../deepseek-harness/apps/desktop-host/src/update-tasks.ts)。
- 桌面内嵌用量和充值页使用服务端专用凭据。现有账号 RPC 只返回安全投影，不包含该凭据；保留内嵌页需要受限的本机主进程连接，不能把凭据放入通用启动描述。参见 [platform-session.ts](../../../deepseek-harness/apps/desktop-host/src/platform-session.ts) 和 [account-controller](../../../deepseek-harness/packages/api/account-controller/src/index.ts)。
- 目录选择和拖拽传递本机路径，同机部署可以保留。Office 依赖由服务端加载，独立 runner 需要保留官方组合。参见 [preload-app.ts](../../../deepseek-harness/apps/desktop/src/preload-app.ts) 和 [desktop-host](../../../deepseek-harness/apps/desktop-host/src/index.ts)。
- 启动器的应用更新检查已指向 `Ghost233/DSH-Workflow` Releases；另有独立的插件检查和更新入口，需要按仓库统一发布的规则收敛。参见 [launcher_controller.dart](../../../macos-launcher/flutter/lib/launcher_controller.dart) 和 [plugin-update.mjs](../../../macos-launcher/runtime/plugin-update.mjs)。

## 设计树

1. 共享业务实例：已确定采用独立服务。
   - 首版部署范围：已确定为当前 Mac。
   - 客户端退出：已确定只断开连接。
   - 启动和登录启动规则：Q3 已确定采用推荐规则。
   - 服务异常退出后的行为：Q4 已确定保持停止、通知用户检查，等待手动启动。
2. 显式服务控制。
   - 有未完成工作的停止和重启：已确定先展示并确认。
   - 无法取得可靠任务状态时的处理：沿用现有 DSH 退出检查，将未知状态作为可能有未完成工作，停止前提示并确认。
   - Web 入口单独启停：Q7 已确定服务与 Web 入口分别控制。
3. 桌面接入。
   - 认证和会话通信：复用 DSH 已有机制。
   - 内嵌用量和充值页：Q5 已确定保留。
   - 更新来源与交付边界：Q6 已确定由仓库统一更新，应用只检查本仓库的 DMG。
   - 可复现构建：由主仓库保存适配并装配到固定上游基准。

## 第二轮结果

- Q3 用户选择推荐的启动、登录启动和退出行为。
- Q4 用户选择异常退出后保持停止，手动启动，并补充必须通知用户检查。此前提出的有限自动重启方案不采用。
- Q5 用户选择保留内嵌用量和充值页。

## 第三轮结果

- Q6 用户指定由本仓库统一更新，不自动更新上游原始版本，检查更新只检查本仓库的 DMG。采用这一统一交付规则，不新增独立的客户端或服务端上游更新通道。
- Q7 用户选择服务与 Web 入口分别控制。

## 实现边界

- 自研服务端插件提供已认证的接入描述，包含实例标识、适配协议和界面注入信息，并提供服务管理所需的任务检查。服务进程的创建、停止和异常通知由独立管理逻辑负责。
- 独立 runner 复用官方 profile、Office 组合、既有配置和持久化数据。保留 JEV、代理监控和已固定的项目插件，不额外创建一套业务配置。
- Electron 适配负责发现并连接实例、加载界面、保留原生能力和断开连接。服务不可用或版本不兼容时明确提示，不另起实例或静默替换服务。
- 客户端连接与 Web 网关复用 DSH 现有认证和会话通信。平台专用凭据不进入通用接入描述、浏览器或日志。
- 启动器和 MacLauncher 的服务控制反映实际拥有关系。DSH 服务与 Web 入口独立显示状态和启停操作；打开桌面端和打开 Web 只打开对应客户端。
- 上游更新检查和安装不能绕过本仓库的 DMG。通过项目集成配置及必要的桌面适配落实，第三方源码仍保持原样。
- 桌面适配源码和固定上游基准由主仓库保存，构建在暂存输入上装配。子模块保持干净，本地与 CI 使用相同输入，版本及插件清单沿用现有权威配置。

## 验收条件

1. 不打开 Electron 即可启动 DSH 服务；桌面端和 Web 报告同一运行实例，并能看到同一工作区、会话和插件状态。
2. 关闭桌面端、浏览器和启动器后，服务与已启动的 Web 入口继续运行。已被服务接收的任务继续执行，重连后可以观察结果。
3. 重复或并发连接不产生第二个业务实例。服务停止时打开客户端只显示不可用，不隐式启动服务。
4. 打开真实启动器后服务自动启动或复用，不强制打开桌面窗口；关闭登录开关不停止当前服务。用户已取消真实 macOS 登录启动验收。
5. 故意使服务异常退出后，服务保持停止，并发出提醒检查的系统通知；启动器已退出时仍能通知。主动停止不发异常通知，通知权限受限或发送失败须如实记录。
6. 有未完成工作或任务状态未知时，停止和重启先显示检查结果并确认。取消后实例与任务保持，确认后仅停止明确选择的服务。
7. 停止 Web 不影响桌面端和业务；停止 DSH 服务后，仍运行的 Web 入口显示服务不可用。重新手动启动服务后，客户端可连接新实例并读取原有持久化数据。
8. 内嵌用量和充值页、账号登录、目录选择、拖拽和 Office 功能通过回归验证。专用凭据不泄漏给普通 Web 客户端或日志。
9. 更新检查只访问本仓库的发布入口，不直接安装上游 DSH 或插件。桌面端退出和更新不携带停止共享服务的隐式操作；实际服务升级按显式停机规则处理。
10. 从干净检出构建的产物包含服务插件和桌面适配，相关本地门禁通过，DSH 子模块无未提交修改。正式发布仅在用户另行要求时执行。

## 实施顺序

1. 实现独立 runner、服务插件和管理逻辑，验证单实例、显式启停、后台存续及异常通知。
2. 接入桌面端和 Web，验证共享状态、退出行为、认证与原生能力。
3. 收敛启动器、MacLauncher 和更新入口，完成可复现构建及完整回归。

## 用户后续调整

2026-10-17 用户要求跳过真实 macOS 登录启动验收，不重启或退出 macOS；只需保证打开启动器后自动启动 DSH 服务。此条更新原 Q3 与系统登录实测要求，归 S06 和 S08。一次启动器启动只尝试一次，已有服务复用；服务后续异常退出仍通知并保持停止，由用户点击启动或重新打开启动器触发下一次启动。通知的真实系统边界验收保留。
