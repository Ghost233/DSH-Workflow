## 要构建什么

用户查看候选配置的变更、执行对照、支持范围和相关检查结果，明确知道候选能否在 DSH 生效。映射和确定性检查失败时，界面显示真实拒绝原因。

## 验收标准

- [ ] 逐类记录任务指导、经验、skills、脚本、工具、子代理及自研插件配置的映射语义、支持字段与拒绝条件。
- [ ] 实验中原版配置表达明确作为中间表示，不把它声称为 DSH 原生配置。
- [ ] 无法映射、越界或未知字段明确拒绝，不静默丢弃，也不改变上游核心。
- [ ] 代理约束、权限、凭据和第三方源码受到固定边界保护。
- [ ] 候选展示来源、适用范围、版本、变更、执行对照与相关检查证据。
- [ ] 配置可用性或相关确定性检查失败时不可采用；缺失证据显示真实状态。
- [ ] 区分客观验证与主观判断，模型或 JEV 的判断不覆盖确定性失败。
- [ ] 支持项与不支持项均有用户可见行为测试，任务失败保留原始诊断与资源收尾结果。
