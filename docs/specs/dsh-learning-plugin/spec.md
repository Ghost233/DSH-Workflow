# DSH 学习插件

正式 Spec：[GitHub #48](https://github.com/Ghost233/DSH-Workflow/issues/48)。跟踪状态以 GitHub 为准。

## 问题陈述

DSH 能执行任务、管理插件和加载 skills，但重复失败、用户纠正与成功做法尚未形成可管理的项目学习过程。用户需要控制是否继续学习、是否使用已有经验，以及哪些改进真正进入日常任务。

单纯保存聊天摘要不足以验证改进。用户希望复用原版 Harness² 完整核心，让候选经历真实试跑与比较，再由用户决定项目采用。学习过程还必须遵守当前工程边界，保留主任务的运行状态和用户文件。

## 解决方案

提供独立的 DSH 学习插件。在 Mac 本机运行随应用交付的 Harness² 组件，由自研适配层连接 DSH。保留原版候选提出、试跑、组合、选择、反思、实验经验库和预算记录。

学习开关与经验使用开关按工作区分别保存，初始关闭。同一工作区的会话共享已采用经验，不同工作区及 worktree 分别隔离。

开启学习后收集当前工作区的新任务证据。用户明确标记任务完成或失败时启动一轮学习，也可通过“学习本次任务”手动启动。历史任务由用户明确选择。每条回复结束不自动重跑整项任务。

学习过程自动生成改进候选。用户查看证据与变更后明确采用，插件再按需提供已采用经验。写入项目默认 skills 目录属于单独的显式导出行为。

## 实现决策

### 核心与适配边界

- 通过外部适配层调用固定版本的原版 Harness²，保留上游源码原样。首个基准版本使用已经完成本机探针的完整提交，并记录来源和许可证。
- 保留原版通用与领域候选、parallel 与 sequential 模式、组合、结果选择、反思、实验经验库和预算记录。初始运行使用原版默认模式，默认递归预算为 k=1。
- 学习插件提供公开控制入口、任务管理、候选管理、项目采用、经验提供和用户界面。适配层满足完整的任务、编辑文件、轨迹、交付物与调用结果契约。
- 原版实验选定结果与项目采用分别记录。原版内部选定不单独证明优于基线，也不授予日常任务使用资格。
- 原版配置表达与 DSH 生效配置之间维护明确映射。每类组件列出支持字段、生效语义、拒绝条件和验收证据。无法映射或越过固定边界的内容明确拒绝，不静默丢弃。
- 允许在实验环境中优化任务指导、经验、skills、辅助脚本，以及可映射的工具、子代理和自研插件配置。现有代理约束、权限、凭据和第三方上游源码保持固定。
- 适配失败、环境缺失或组件不支持时报告真实状态，不自动改用自写的简化学习流程。

### 任务、模型与实验

- 学习任务包含明确的任务与输入范围、来源会话、模型配置和工程验证声明。用户标记完成或失败不直接等同于收益验证通过。
- 自动收集只覆盖开启学习后的当前工作区新任务。历史任务由用户选择，并形成明确学习任务。
- 任务试跑、候选生成、选择和反思均通过独立 DSH 会话执行。实验开始后固定来源模型配置，配置不可用时明确失败，不静默切换。
- JEV 只辅助局部语义判断，不代替完整生成、确定性验证或项目采用。
- 同一 DSH 服务端实例全局同时运行一个学习实验。默认 k=1，不自动增加递归预算。等待中的任务与活动实验分别显示。
- 仅消费工程已准备的可重复实验环境和固定验证命令。环境缺失时标为待实验，保留具体缺口。
- 工程初始化负责工具链、依赖与缓存。学习功能不识别语言或包管理器，不安装依赖，不复制或摘要依赖树，不向工作区注入依赖目录。
- 每次试跑绑定同一声明的输入基线和验证要求。隔离实验与日常工作区，保留用户未提交及未跟踪文件，不自动 stash、覆盖、移动或删除这些文件。
- 实验遵守 DSH 原生沙箱与审批。重放范围明确，外部副作用不能仅因开启学习而获得授权。
- 过滤学习插件自身实验记录并去重，避免学习过程循环触发自身。
- 记录来源版本、实际执行次数、模型用量、可获得的成本与取消结果。缺失的成本或证据明确标为未知，不能记为零或通过。

### 开关、保存与采用

- 以 DSH 工作区根目录隔离项目经验库和两个开关。同一工作区多个会话共享，不自动跨工作区迁移或共享。
- 学习开关与经验使用开关初始关闭。工作区内的操作不改变其他工作区的状态。
- 关闭工作区学习时，停止接收新样本和安排新调用，取消或收尾该工作区所属实验。关闭整个插件时清理插件拥有的全部运行资源，不中断主任务或其他插件。
- 无法立即取消时显示取消或收尾状态；结束后不继续自动采用结果。应用中断和重启保留真实状态，不自动把中断实验重放为成功。
- 候选至少保留来源、范围、变更、执行对照、验证证据和版本。实验结果、项目候选和已采用经验具有不同状态。
- 配置可用性和相关确定性检查是采用门槛。失败或无法映射的候选不可采用。
- 对缺少客观收益标准的合法候选，展示执行对照与模型判断，允许用户明确人工采用，并保留“人工判断”标记。不得标为客观验证通过。
- 已采用能力先保存在插件管理的项目经验库，通过独立入口按需提供。候选与未采用结果不能进入日常经验提供范围。
- 经验使用关闭或撤回后停止后续发现和加载。当前会话已读内容仍保留，干净对照使用新会话。
- 显式导出面向项目 skills 及其相关资源。展示写入范围并检查冲突，保留已有文件与人工修改。导出和撤回均保留版本与归属证据。
- 撤回插件经验控制后续使用；已导出项目文件单独处理，不通过插件停用自动覆盖项目内容。

### 本机交付与集成

- 独立 Harness² 运行组件优先在 Mac 本机运行并随应用交付。构建阶段固定来源、运行时和内容摘要，保留许可证。
- 应用启动时不下载运行环境，用户无需另装 Python 或启动 Linux 服务。缺少组件或内容校验失败时明确报告。
- 源码启动、应用资源、包入口、测试发现和交付校验接入同一自研插件版本。
- 日常启动继续使用现有无参数入口。保留 JEV 与原生代理监控，并逐项如实报告插件结果。
- 学习与经验使用开关不替代 DSH 的 profile 级插件总开关。界面区分已保存状态和实际运行状态。

## 测试决策

Q12 已确认以 DSH 插件的公开操作和用户可见行为作为主要验收入口。测试执行真实 Harness² 核心，并用可控模型响应提供可重复的完整流程，避免只测试内部实现。

重点覆盖：

- 默认关闭、状态持久化、工作区隔离和同工作区跨会话复用。
- 新证据收集、完成或失败触发、手动历史任务与自身实验过滤。
- 真实核心的两种模式、模型配置固定、任务执行、编辑文件、轨迹和经验库契约。
- 配置映射、保护边界、不支持项、真实失败与缺少证据的状态。
- 全局单实验、默认 k=1、环境缺失、取消、插件卸载和中断恢复。
- 候选展示、采用门槛、人工判断标记、按需加载、撤回与导出冲突。
- 主任务、已有 JEV 与监控、用户文件及主动停用状态的保留。
- 原版来源与内容校验，以及源码启动和打包应用的一致性。

复用仓库现有完整测试入口，并把新插件纳入测试发现。验收覆盖完整项目测试、客户端产物核对，以及涉及启动器变更时的 Flutter 检查。验证命令按仓库约定固定，新增运行组件与客户端检查由对应 Ticket 确定，并接入完整验收入口。

每次验证记录命令、源码版本和真实退出码。构建输入变化后更新对应产物。真实模型效果实验单独记录，既有无模型 demo 不能代替效果验收。现有发布工作流不代替本地完整检查。

## 范围之外

- 模型参数训练。
- 修改、修补或恢复第三方上游补丁，以及修改 DSH 或 SDK 上游源码。
- 将原版所有配置文件原样视为 DSH 原生兼容。
- 自动更改人工代理约束、权限和凭据，或自动将候选投入日常任务。
- 自动搭建工程依赖、共享工具链、复制依赖树和延长失败验证的超时。
- 默认跨工作区共享经验，或自动扫描全部历史会话。
- 自动安装学习过程生成的任意第三方插件或新的 Host 代码。
- 改变监控模块职责，或恢复已移除的 SoL、Synapse。
- 默认多轮递归或多实验并行。
- 正式发布应用、推送发布 tag 或切换用户正在运行的服务。
