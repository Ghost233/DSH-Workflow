# 跨会话依赖缓存身份修复

## 根因与修复边界

原安装输入直接摘要调用进程 PATH。FNM 目录别名和临时命令目录变化会使相同工具链失效。仅把该摘要替换为 executable provider 映射也不够：安装脚本能够读取 PATH 原文、调用路径以及 dirname 下的资源。因此本次修改真实安装子进程的路径，并绑定其实际输入。

自研依赖准备模块从绝对 POSIX PATH 的 first-wins 命令解析结果建立内容地址工具目录；目录中的命令指向实际可执行目标，绑定目标元数据、运行时、env launcher 和 shell 身份。按现有 artifact、文件锁与原子发布方式生成只读命名空间；复用时校验清单、链接目标和元数据。

版本探测与安装都通过固定 argv 的 `/usr/bin/env PATH=<stable-path> ...` 执行。dependencyInstallInput 仍摘要这个真实 PATH，且绑定工具身份；准备耗时等 metrics 不进入 identity。不修改 process.env、终端配置、DSH 设置、权限、模型或第三方源码。

相对/空 PATH、不支持的解析环境或不能枚举的目录保留原始环境及保守身份，不假装能安全归一化。稳定命令目录定义安装子进程的新调用路径；依赖原调用目录资源的程序如果不兼容，会由真实命令失败报告，不能偷偷换回原 PATH 或当作通过。真正工具内容的变化通过目标路径、inode、size、mtime、mode 等元数据识别；不在热路径摘要全部二进制文件，也不声称可检测保留这些元数据的恶意外部篡改。

## 验证

红测试实际复现同工具目标因临时 PATH 失效，6/7 通过、1项精确失败。修复后最终定向 44/44 通过，覆盖实际 PATH/$0 相同、工具/优先级变化失效、只读命名空间污染拒绝、并发发布、安装恢复与旧执行隔离。

真实规模证明 **13/13 通过**，依赖 base 为 1,761,456,007 字节，耗时约 7 分 20 秒。两个真实独立进程使用不同临时 PATH，最终都命中与主进程相同的缓存身份；若尝试再次安装，用例会在派发安装前明确失败。

- 11 次热复用：0 次安装、0 次整树复制、0 字节共享 base 摘要；每次仅复制并摘要 545,493 字节私有元数据。
- 2 次冷安装分别为首次采用新的实际安装环境、显式 lockfile 输入变化；恢复原输入后重新命中原 base。
- 并行验证、失败命令后重试、业务源码变化复用、共享 base 写入拒绝、私有 overlay 污染拒绝均通过。
- 全部场景累计复制 333,797,512 字节，包含两次冷封存的硬链接归一化；不能把“0 次整树复制”解释为完全没有复制。
- 工具身份扫描包含 1,896 个有效命令，环境准备耗时约 240–674 ms；没有把真实工具变化从缓存身份中删去。

独立只读复核未发现阻断性接线问题。真实规模测试后再次核对本次代码摘要，与测试开始时一致。机器报告见 [report.json](report.json) 与 [真实规模原始报告](dependency-proof-report.json)。

本次实证运行于 macOS/POSIX。Windows 仅覆盖保守回退分支，不声称完成 Windows 实机验证。`.npmrc` 内容本身纳入安装输入，但其中绝对 script-shell 指向的外部程序元数据尚未单独解析；本次冻结项目不存在 `.npmrc`，此边界不影响当前证明。

旧缓存与原工作流保留，剩余恢复额度为4。完整 Coinhub 业务验收不因本项测试而宣告完成。
