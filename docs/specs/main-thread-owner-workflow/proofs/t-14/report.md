## 已证明可复用的部分

saveState不只是给rename套锁：prepareState(current)在跨进程写锁内读取当前值并执行计算。使用真实函数与T-13账本，九组存储场景完成，包括最后额度竞争、同请求并发重放、三个SIGKILL窗口、坏数据/保存失败及旧revision拒绝。内存已扣减但尚未写入时被杀不留下半扣；死进程的写锁保护期内拒绝，真实等待约30.3秒后恢复。该接缝可作为后续持久领取适配的基础。

## 阻止完整接线的部分

1. 根问题来源还没有统一、持久的Runtime映射。现有义务引用可作为基础，但模型新声明ID不能自动获得新额度；旧恢复指纹随计划版本变化且归一路径，不满足稳定根问题合同。
2. runChild/provider还没有贯通预算request/attempt与预留session/prompt身份。现有provider先保存Owner session绑定再提交prompt，创建或绑定失败不会继续；这项正向顺序值得保留。但完整重启对账尚未被证明，已有resume接口与session日志也不能自动消除prompt接纳后、回执保存前的不确定窗口。

两组真进程会话探针使用真实runChild/provider和模拟服务，证明底层直接重放产生不同身份；未经过完整Owner入口及lease，因此不声称生产已经自动双启动。存储保存后的replayed也只停在夹具对账点，没有真实恢复执行。
