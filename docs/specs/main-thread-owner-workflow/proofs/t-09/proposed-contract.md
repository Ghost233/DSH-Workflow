# V-03 / B-04 恢复预算拟议合同

本文件是T-09技术验证产物，**未实现、未激活的技术方案**。保留R4需求，不把以下数字写入生产配置。现有“策略集合加遥测计数”不足以实现持久预算，详见[证据报告](report.md)。

## 身份、账本和领取

问题以稳定 `rootProblemId` 表示，引用T-02义务/来源合同；任务、Owner、attempt或PlanRevision换名不改变问题。已有问题拆成多个执行段时由编排者明确携带根问题及派生引用，Runtime校验继承；禁止以新task ID暗示新预算。真正新增且不相关的问题取得新ID，但仍消费同一Workflow总预算。

Workflow持久状态新增版本化预算账本。问题记录含 `limit/used`、待决/耗尽状态、关联义务与证据；Workflow另有 `totalLimit/totalUsed`。尝试记录包含唯一 `attemptId`、根问题、task/Owner/执行版本、领取状态、固定 `deadlineAt`、租约标识与结算结果。`usedStrategies`仅选择动作，不能作为预算余额。

所有会消费恢复额度的入口（Supervisor派发、直接Owner恢复、自动超时恢复、产生执行尝试的局部重规划）共用一次领取事务：在Workflow锁内校验版本/授权及两级余额，以幂等请求ID查询旧attempt，同时扣减两级余额并持久化reserved记录，完成持久化后才能启动外部工作。流程恢复应复用已reserved但未启动的attempt，不能重复扣减或再发一个新attempt。持久化失败禁止启动；启动结果不确定时先对账会话/租约，不猜测成功或退款。

领取后次数不因取消、崩溃或新证据自动退回。重复结算只能补完同一attempt，不再扣/退；停止/超时结算与任何额度变更有可审计记录。并发领取通过同一账本串行化，并测试相同请求、不同请求以及父/子同时领取。恢复次数的计量单位是一次外部恢复尝试，不是一次工具读取、失败通知或策略计算。

## 新证据和派生

新证据必须通过T-03的来源、版本和问题关联校验。已见过的事实指纹集合单调保留；A→B→A不能被当作第三份新事实。新证据允许重新选择下一动作，但不减少任何 `used`、不增加 `limit`。独立T2事实不得重置T1恢复策略租期；所有子节点共享其root问题额度，Workflow累计额度也不因任务拆分、重建候选或进程重启归零。

计划版本激活时，账本的继承映射需与执行版本一起生效。新版本声明的来源不完整时拒绝激活相应恢复节点，不能先运行后补ID；此事务接缝依赖B-01，不能把纯迁移函数验证当作全链路事务完成。

## 超时、释放和局部停止

当前 `onTimeout.afterMs` 保留“空闲/无进展超时”语义，另增每次尝试固定硬截止时间；心跳不得延后硬截止时间。截止后持久标记stopping并请求取消，确认旧会话已终止、旧租约已失效/被安全隔离，才释放可释放的槽位并允许同Owner下一attempt。取消未完成时保持该Owner不可重入，其他不共享Owner/资源的任务继续。不能靠把task先改pending来表示资源已释放。

两级预算耗尽时形成技术失败报告，记录根问题、已用次数、最后事实、已试策略及现场位置。停止对应问题及其必要后继；调度入口、主线程控制投影与派发确认必须对独立任务有一致语义。本次已有实际Supervisor领取T2的正例，应保留，不能因补账本倒退为全局停止。

## 有限初始值与兼容方案

建议用于后续受控验证的初值：每个根问题最多3次恢复尝试，每个Workflow最多12次恢复尝试，每次尝试硬截止30分钟。3次对应当前预算错误的3种非终止恢复策略，12次是两级预算验证的暂定有限总量；30分钟沿用当前默认空闲超时量级，但将硬截止作为新增独立字段。**本地毫秒级夹具不能校准模型耗时或成本，12和30分钟没有线上性能结论；生产默认值需代表执行包测量后确定。**初次业务执行不算“恢复”，仍必须有独立单次硬截止；涉及Workflow总模型成本上限须另外明确计量合同，不用恢复次数冒充token成本。

新账本显式版本化，新Workflow使用冻结的正整数上限，不接受缺省为无限、零或负数。旧active Workflow不从 `recoveryCount` 反推已用预算（本次证明它不等于尝试数），也不悄悄把旧 `maxAttempts` 提示改成执行上限。旧现场保留原模式与原审批，明确显示legacy；迁入新模式必须有可核验的历史计量和一次性迁移记录，无法重建的部分停止相关迁移，先保留现场并报告技术缺口。

`maxPlanRevisionTurns/maxPlanRevisionFailures`、`maxParallelOwners`、`maxTokens`各保留原用途；不得映射为新的总预算。若要把原 `onFailure.maxAttempts` 用作新问题上限，应仅在新协议中定义并校验，不能对旧任务追溯改变语义。

## 下一实施边界和所需证据

先细化一个持久账本与领取接口实现工单，再接入各Runtime入口；最后处理B-01版本/派生事务与超时取消结算。当前不创建假就绪DAG、不修改生产。

必须补：reserved落盘前/后及启动前/后真实进程中断；相同attempt重放及并发领取；父子共享与独立问题共享总额度；已核验新事实不退总额度；A/B回放；真实会话硬截止及取消延迟/租约释放；受影响问题耗尽而T2实际启动。T-09本次是拒绝现有路线的证据，不是这些未来用例已通过。
