# T-14 验证恢复领取的持久事务与启动对账

规格：[R4第12节（R4-V03-1）](../../../superpowers/specs/2026-09-10-main-thread-spec-ticket-owner-dag-design.md)。合同：12.2、12.3。来源：[T-09证据](../proofs/t-09/report.md)；全局状态与唯一共同场景见[进度索引](../progress.md)。技术验证已交付部分存储正向与完整适配否定证据；生产AC未通过。

## 交付行为与范围

给出一个经实际进程中断和并发验证的账本存储/领取/启动对账方案，或明确拒绝现有适配并列实现缺口。

范围之外：不修改生产持久化/锁/会话代码、不把内存Runtime重建当进程中断，不顺手造通用数据库或预算平台。

## 模块与并行边界

只写proofs/t-14的临时夹具与证据；只读runtime的writeJsonAtomic/saveState/withWorkflowLock、Owner lease、Supervisor reservation与会话启动接缝，消费T-13模块。主线程维护文档，原生产测试不改。

所列模块是执行前核验的候选范围，不代表已获得写入归属；同一文件同一时间仅一个写入者，主线程独占规格、进度和Git操作。

## 前置与解除条件

逻辑依赖：[T-13](t-13-recovery-budget-ledger.md)。

T-13须交付稳定状态转移接口及幂等反例；否则无法验证被持久化的同一合同。T-14即使开发完成但结论是否定，也不自动解锁T-15。

## 交付要求

- 固定根问题来源生产者：已有义务引用或Runtime首次失败记录；同一未解决问题重放/换attempt复用，真正新问题需要可核验来源，不能由文案hash或模型自报决定。
- 固定请求ID、attempt ID和实际会话/外部启动ID的关联及恢复对账入口；旧结果和状态不确定时明确停止/恢复条件。
- 在读取最新账本、扣减保存前后、reserved后启动前、启动成功但回执前分别杀死受控子进程并重启；区分进程崩溃与未覆盖的断电持久性。
- 不同进程争抢最后一份额度、同请求重放、损坏或不完整状态、保存失败、存储失败时不得启动；证明不是仅写锁保护rename而读改写仍竞争。
- 若现有会话API/锁/存储不能支撑幂等对账，列确切文件、最小接口和新的实现前置，回填12.2；不在本工单内补生产。
