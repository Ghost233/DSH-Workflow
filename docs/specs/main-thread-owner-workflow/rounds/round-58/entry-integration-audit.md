# 下一步入口接线的只读核对

R58候选冻结后核对当前runtime：planWorkflowIntents与reviewPendingPlanRevision整体持有withWorkflowLock；锁实现将新operation链接到同workflow前序Promise，不可重入。新reconcileReplanSession自身在短状态事务与provider回调取相同workflow锁，因此不能直接在旧入口持锁区内调用并等待，否则出现父调用等待child、child等待父锁的确定性死锁。

下一轮应先在短事务固定来源/逻辑步骤/prompt/候选父版本，离开workflow内存锁后执行外部会话，最后通过最新状态事务核对来源、版本与候选唯一性后应用结果。规划资源租约负责同一workflow规划操作排他；不能靠延长超时或删除绑定检查解决锁嵌套。实际planWorkflowIntents的旧saveState(state)还持有外部调用前快照，接线时需要改为新鲜状态回调，防止覆盖已经持久的预算/会话记录。

候选Review当前用candidate.planDigest构造reviewState，但恢复来源由active plan固定。接线需分别保存来源执行版本与候选输出digest，不能把candidate digest覆盖origin，也不能把Review通过等同于激活新版本；后者属于T18边界。

原requestValidatedPlannerPlan/Review各有最多两次物理runChild。新适配成功观察提交后仍T13 running；只有完成语义判定与持久结果记录后，才能为失败领取下一ordinal。原循环不能外层领一次后内部免费调用两次。consultPlanningOwners的每个外部child也需各自物理领取；不能由Planner的一份预算覆盖咨询。

此文为当前源码接缝核对，未声称上述未连接路径已发生生产死锁，也未声称实际入口已受限。
