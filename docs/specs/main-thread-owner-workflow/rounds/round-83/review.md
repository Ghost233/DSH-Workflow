## 首次候选确认发现

1. P2取消传播：Runtime提供的物理lease检查忽略合成取消信号，内核只调用该回调。授权回复后或Git等待期间的取消可能继续推进后续阶段。修复应由内核在物理检查前后核验signal、Runtime闭包显式核验、grant发布前核验；保留已发生的原始授权/Git事实，恢复仍用原事务。
2. P2证据缺口：现有after-index-sync与after-snapshot均在后续journal写入之后，缺少index rename→journal、snapshot publish→journal的精确进程中断证据。现有恢复分支未发现错误，需补这两处实际SIGKILL，不扩大到任意断电保证。

曾提出“Spec修订必须重新获取grant”的问题，经核对实际代码和授权分层后撤回：本入口复用的是明确展示的文档提交能力，原始implementationScope和initialSourceDigest保持不变，未激活任何DAG。T26/T27必须消费原始范围并核验实际执行授权，不能把checkpoint成功等同新版已获实施授权。

首次冻结候选除此无确认P1/P2。两项确认问题进入候选2定向修复与复审，不能用首次测试通过代替关闭。
