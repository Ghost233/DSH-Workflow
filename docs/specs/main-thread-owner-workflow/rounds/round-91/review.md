# R91 实现复核

## 结论

未发现阻止 T18 标记为开发完成的问题。实现满足工单的真实入口要求：版本继承不是离线迁移函数；它在根会话批准的 PlanRevision 事务中生成、完整导入验证并与计划一起保存。预算历史不可变，缺映射关闭处理，派生目标继续消费原 root，旧 attempt 可按原身份结算。

## 复核要点

- 恢复账本的起始执行版本不会在激活时被伪装成新建账本；当前版本必须由无断点的版本边链到达。
- 每个开放 root 都需要新版本目标。保留 task 自动映射；恢复候选只从固定来源、composite 关系和已选择 handoff 的文件覆盖关系增加目标。
- 同一子版本 task/Owner 不能归属两个 root；根、来源、版本、revision 或字段被篡改后，整个 admission 导入失败。
- 两个批准调用竞争同一 pending candidate 时只有一个成功；失败调用看不到可重复激活的候选。
- 跨版本运行中的恢复 attempt 使用旧 intent 结算，版本切换没有第二次 reserve，也没有把旧请求重新解释为当前授权。
- 连续两轮版本、拆节点、改名、跨 Owner 与独立 Runtime 并发领取都由真实 Runtime/持久状态测试覆盖。

## 保留边界

本轮使用显式测试配置，没有决定生产默认总次数、单问题次数或 hard deadline。代表执行包测量、新 Workflow 默认写入恢复协议和 legacy 活动现场兼容由 T19承担。T18的开发完成不表示B04或CA01集中验收通过。
