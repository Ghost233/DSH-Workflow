# R57 来源路由只读核对

独立t16_cancel_proof核对两类handoff生产者：requestHandoff来自live Owner，queue含source owner/task/session；recordHandoffs也可能来自正常completed partial commit，此类不能伪造成Owner失败。verification失败重开既有handoff也需绑定真实verification receipt，并保留原root。当前queue字段不统一，没有统一attempt provenance；后续须在创建时固定origin/源版本，重开追加失败trigger，不依据pending文字猜测。

首次免费Owner真实failed/blocked记录本身可以为首次replan领取建立root；不能要求先有付费Owner前序。R57沿既有validatedFailureSource及continuation支持这两类，尚未自动解析handoff/cycle触发器。旧handoff缺来源不意味着永久禁用正常handoff，需要区分正常需求与恢复，并补生产入口。

planWorkflowIntents除Planner还有consultPlanningOwners的实际Promise.all(runChild)；有咨询时每个child及Planner都应单独领取且共用root。requestValidatedPlannerPlan/Review两次内部调用都需独立持久ordinal，不由外层重复扣。review必须继承候选所保存的origin；handoff多root不能任选其一给整个child计费，应按可执行局部任务拆批后分别启动。

下一步触发快照/operationId由受信Runtime固定，然后会话启动和结果应用双侧核验来源/版本。R57内部reservation不是启动许可，不把纯T13回执测试当成实际Planner结束证明。
