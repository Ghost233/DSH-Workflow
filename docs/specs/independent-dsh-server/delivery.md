## 本地门禁与证据规则

沿用项目现有入口：根项目客户端产物检查和完整项目测试、Matt 面板构建与测试、Flutter 的统一检查入口，以及生产 Desktop 和实际 Wrapper 的构建与验收。各阶段先运行受影响用例，再固定候选执行适用完整门禁。无需更改的上游产物仅在输入与环境均未变时复用已有验证。

测试以用户确认的启动器操作和正式 MacLauncher SDK 为主要接缝，真实服务、桌面端和浏览器用于观察外部结果；登录启动及系统通知另做系统边界验收。测试资源隔离，不切换用户当前服务，不以模拟通知、旧架构结果或强制回收代替通过。

每次执行记录源码版本、命令、工具版本、真实退出码和原始日志。观察超时先查询原作业，不重复启动同一长任务。所有已确认 P0/P1/P2 修复后重新验证相关路径；最终完整检查覆盖实际待提交候选。

## 最小真实路径预检

`.build/independent-dsh-server/preflight/packaged-host-result.json` 记录了官方 alpha.5 打包 Host 的隔离执行。探针退出 0，验证未认证 RPC 401、token 登录 303、认证后插件读取、HTML 与 JavaScript 资源 200，以及真实 Host PID 和 0600 私有就绪记录。

该结果只证明现成官方运行资源和最小 HTTP 路径可用，不证明新服务管理逻辑、桌面接入、浏览器渲染或全部规格已经完成。
