# DSH 独立服务与桌面、Web 共享实例

正式跟踪：[GitHub #25](https://github.com/Ghost233/DSH-Workflow/issues/25)。GitHub issue 是执行状态来源，本地文件保留规格副本。

## 问题陈述

当前 DSH 业务实例由桌面应用创建和持有。真正退出桌面应用会停止业务，浏览器也会失去访问能力。启动器退出时会回收 Web 访问服务，因此用户必须保留多个应用进程才能维持访问。

用户希望先启动独立的 DSH 服务端，再让桌面客户端和 Web 连接同一个实例。关闭客户端后，服务和已经接收的任务应继续运行。服务异常退出后应保持停止，通知用户检查，再由用户手动启动。

桌面适配和项目插件还需要随本仓库统一发布。直接更新上游原版会绕过适配，也可能改变已固定的插件版本。应用的更新检查应只检查本仓库的 DMG。

## 解决方案

在当前 Mac 上提供独立常驻的 DSH 服务端。由 DSH 启动器提供明确的服务启停操作，桌面客户端和 Web 只连接已有服务。服务端与 Web 访问服务分别控制；退出启动器后，已经启动的服务和 Web 入口继续运行。

采用自研服务端插件、项目运行编排和最小桌面接入适配。复用 DSH 已有的认证、会话、工作区、插件和 Office 能力，保留现有配置与持久化数据。更新统一随本仓库的 DMG 交付。

## 实现决策

- 首版仅覆盖当前 Mac 的常驻服务、本机桌面端、本机 Web 和已有局域网 Web 访问。工作区路径仍属于同一台 Mac。
- 服务端业务生命周期归独立管理逻辑所有。启动器、桌面端和浏览器退出时仅释放自身资源，不停止业务或回收已经启动的 Web 入口。
- 普通 DSH 插件在 Host 启动后加载，无法替换 Electron 创建 Host 的行为，因此采用服务端插件与必要桌面适配的组合。
- 复用官方 Host 的 profile、Office 组合、任务检查及既有项目装配。独立管理逻辑可以持有官方 Host 的私有进程通信，无须复制一套上游业务实现。
- 自研服务端插件提供实例识别和桌面接入所需的描述信息。项目运行编排负责服务创建、停止和故障通知，插件不负责启动自身所在进程。
- 桌面客户端改为发现并连接已有实例，取得界面注入信息并保留原生能力。客户端断开不能转化为服务停止请求。
- 复用 DSH 现有认证和会话通信。本机控制接口仅供受保护的本机管理端和 Electron 主进程使用，不通过局域网 Web 网关暴露。
- 用量和充值页的专用凭据仅传给受限的本机 Electron 主进程，不进入通用接入描述、普通 Web 客户端或日志。
- 服务不存在或接入版本不兼容时明确提示。客户端不得另起业务实例或静默替换正在运行的服务。
- 服务和 Web 入口分别显示状态并提供操作。停止 Web 仅关闭浏览器访问；停止服务后，保留的 Web 入口显示服务不可用。
- 停止、重启和实际服务升级前，复用现有任务检查。未完成工作包括运行中的代理、待处理消息、后台任务及相关定时提醒；状态未知时按可能存在未完成工作处理。
- 有未完成工作时先展示并确认。取消后保持原实例和工作；执行停止前需防止检查后新接收的工作绕过确认。
- 服务意外退出后保持停止，不自动重启。独立管理逻辑发送系统通知，提醒检查日志；运行编排不额外重发任务，任务恢复沿用 DSH 行为。
- 开启登录启动后自动启动服务，不强制打开桌面窗口。关闭登录启动不应隐式停止当前正在运行的服务。
- 保留既有配置、凭据、工作区、会话历史、JEV、代理监控和已固定的项目插件，沿用现有权威配置来源。
- DSH、桌面适配和插件统一通过仓库固定版本并随 DMG 交付。应用内的上游原版更新及单独换包通道不得绕过这一规则；组件升级在仓库维护流程中完成。
- 检查更新只检查 Ghost233/DSH-Workflow 的正式 DMG。客户端退出或检查更新不隐式锁定、停止共享服务；涉及服务替换时遵循显式停机和任务确认规则。
- 桌面适配由主仓库保存，在构建暂存输入中装配到固定上游基准。DSH 子模块保持干净，其他上游及第三方源码保持原样。
- 新启动语义替代旧规格中“由 Desktop 持有后端”“缺少后端时打开 Desktop”的规则；统一交付替代旧应用内单独更新插件并重开 Desktop 的规则。

## 测试决策

用户已确认：以现有启动器操作和 MacLauncher SDK 服务接口作为主要测试接缝。通过这些真实入口驱动功能，使用真实 DSH 服务、桌面端和浏览器观察结果。登录启动与系统通知另做系统边界验收。

- 优先扩展现有应用和 SDK 验收入口，不为每个内部模块新增独立测试协议。不根据私有函数调用次数或类结构判断业务是否通过。
- 借鉴现有 Flutter 控制器、管理界面、SDK 会话、真实桌面 Host、Web 认证和生命周期测试。旧测试依赖 Desktop 持有后端的断言需要按新规格更新，历史成功不能替代新架构验证。
- 共享实例通过实例标识、实际服务进程和一致的工作区、会话及插件状态验证，不能只比对相同地址或固定 ready 值。
- 不打开桌面客户端启动服务，再分别连接桌面和 Web。关闭所有客户端及启动器后，观察同一服务仍运行、已接收任务继续执行，重连后能看到结果。
- 验证服务停止时打开客户端不会隐式启动服务；重复、并发和重连不产生第二个业务实例。
- 分别验证 Web 回收、服务停止、取消停止、任务检查失败、检查后任务变化及手动重启，确认资源和业务影响符合操作范围。
- 故意使服务异常退出，观察保持停止和系统通知。启动器退出后重复这一场景；主动停止不应产生故障通知。
- 区分通知请求提交、系统授权和实际通知展示。模拟发送成功不能当作用户收到通知；权限拒绝、发送失败或缺失系统展示证据须明确记录。
- 登录启动在受控系统边界验证启用与停用，并确认没有强制打开桌面窗口。使用隔离配置和自有资源，不改动用户正在使用的服务或系统设置来替代验收。
- 回归账号登录、内嵌用量和充值页、目录选择、拖拽及 Office。验证普通 Web 客户端和日志无法取得平台专用凭据。
- 验证错误认证被拒绝，Web 访问权限规则保留；服务切换后旧实例凭据和连接不能误用为新实例。
- 观察应用更新检查的真实目标，确认只检查本仓库的正式 DMG，运行端不直接安装上游 DSH 或插件。
- 从干净检出构建实际应用，确认服务插件、独立管理逻辑和桌面适配均进入产物；执行受影响模块测试、完整项目门禁和原生回归。
- 记录源码版本、真实命令、退出码和原始证据。取消、超时、未知、缺失证据或强制清理不能记为通过，第三方失败按维护边界如实报告。

## 范围之外

- 跨机器桌面连接、远程 Linux 部署、远程工作区路径和文件传输语义。
- 多用户账户隔离及新建一套认证、会话或模型执行协议。
- 服务异常退出后自动重启、自动重发任务或替用户修复故障。
- 重写 DSH 核心业务，或修改其他上游和第三方插件源码。
- 恢复已移除的插件、SoL、Synapse 或历史取消的适配计划。
- 在运行端直接更新上游原始 DSH、桌面应用或插件包。
- 自动安装本次应用、切换用户现有服务或执行正式发布。正式发布须另行明确要求，并遵循发布流程。
