## 要构建什么

用户保存并同时启用多套 JEV 引擎配置，让不同消费插件通过不同调用模型名同时使用对应服务；修改、停用或删除配置时，在途请求和后续请求各自遵守清晰的生命周期规则。

实施须等待用户明确恢复开发。修改留在自研插件和项目集成层。

## 验收标准

- [ ] 用户可以保存多套配置并同时启用；通过两个不同调用模型名的并行请求可验证各自选择正确 URL、上游模型名及凭据，没有全局唯一选择覆盖另一消费方。
- [ ] 已启用配置的调用模型名必须唯一。新增、启用或修改造成冲突时明确提示并拒绝冲突状态，不静默选第一套；上游模型名可以重复。
- [ ] 修改配置只影响新请求；修改时已经发出的请求仍使用开始时固定的配置完成或超时。
- [ ] 允许停用或删除被消费插件引用的配置。在途请求不被该操作中断，新调用明确返回配置不可用，不使用其他配置代替。
- [ ] 删除引擎配置不自动删除 DSH 凭据，用户仍可以经标准凭据接口管理它。
- [ ] 从标准设置操作到并行命名调用和连接测试结果完成真实 Host 验收；模拟上游能区分目标配置并验证在途修改、停用、删除，不调用付费模型。
