## 父项

[Spec #12：统一 JEV 中心与 DSH 原生代理监控（仅检测）](https://github.com/Ghost233/DSH-Workflow/issues/12)

## 要构建什么

用户在原生主代理或子代理的模型请求出错、异常中断或明确未完成时，可以从监控告警知道哪个请求结束、接口提供了什么原因，而不是只能看到任务突然停止。

实施须等待用户明确恢复开发。复用已有观察和告警呈现，不改变代理终态或恢复策略。

## 验收标准

- [ ] 实际模型或代理错误、能够证实的异常流中断、空结果或缺少正常结束标记的 EOF、明确输出限制未完成终态分别形成有具体原因的告警。
- [ ] 告警通过同一 DSH 列表、持久日志和 macOS 通知提交路径呈现，正确关联主代理或子代理及对应请求，不因重复终态事件重复提交同一告警。
- [ ] 正常完成、正常工具衔接和主动取消不被标为异常结束；已结束请求不继续累计无输出，新请求从独立状态开始。
- [ ] 对仅有正常结束标记的部分回答不声称必然识别隐藏故障，展示的原因来自公开接口证据。
- [ ] 监控不改变原请求终态，不自动取消、重试、换模型或发送干预消息；错误展示和日志不暴露密钥或认证请求头。
- [ ] 通过真实 Host 的公开模型流和代理终态模拟逐类验证异常与正常结束，包括主、子代理和后续正常请求，不依赖 JEV 或付费模型。
