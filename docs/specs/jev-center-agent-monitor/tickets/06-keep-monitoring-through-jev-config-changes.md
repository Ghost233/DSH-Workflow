## 父项

[Spec #12：统一 JEV 中心与 DSH 原生代理监控（仅检测）](https://github.com/Ghost233/DSH-Workflow/issues/12)

## 要构建什么

用户在正常开发中同时使用多套 JEV 配置，并修改、停用或删除监控引用的配置时，可以看清语义判断是否可用；已发出的判断按原配置结算，后续调用遵守新配置，确定性监控与代理任务继续。这张工单交付多配置中心和实际监控消费者之间的完整生命周期行为。

实施须等待用户明确恢复开发。本工单不授权切换或重启用户正在使用的 DSH 服务。

## 验收标准

- [ ] 同一 Host 中，监控主、子代理共用所选调用模型名，另一个消费方同时使用另一已启用名称；两者正确路由、互不覆盖配置或判断状态。
- [ ] 监控判断在途时修改、停用或删除所用引擎配置，原判断仍按原配置完成或超时；下一次判断使用新配置或明确不可用，不从其他名称自动选备用引擎。
- [ ] 允许删除或停用监控正在引用的配置，DSH 凭据保留。配置确实缺失、停用、鉴权失败、服务错误及超时分别显示准确的红色不可用原因；配置重新可调用并取得有效判断后状态据此更新，不把引擎可用性变化当作代理恢复。
- [ ] 未知或失败仍按语义规则清零异常计数且不记录代理恢复。无输出和异常结束检测不受上述配置操作或请求失败影响，代理任务继续运行，未新增引擎故障系统通知或自动处理行为。
- [ ] 通过项目既有无参数日常启动入口的装配，在隔离验收实例中验证两个自研插件和其他启动插件的真实结果；不能通过额外调用参数掩盖装配问题，不修改第三方或 DSH 上游源码。
- [ ] 从标准设置操作、原生代理进展、中心并行请求到界面状态和告警记录完成交叉验收，模拟上游覆盖在途改动及错误；日志和界面无密钥或认证请求头，不调用付费模型、不切换当前运行服务。
