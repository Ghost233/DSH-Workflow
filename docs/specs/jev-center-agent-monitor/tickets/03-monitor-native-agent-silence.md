## 父项

[Spec #12：统一 JEV 中心与 DSH 原生代理监控（仅检测）](https://github.com/Ghost233/DSH-Workflow/issues/12)

## 要构建什么

用户启用代理监控后，DSH 原生主代理和子代理的模型请求长时间无输出时，按可配置的检查间隔和连续次数收到告警。告警进入 macOS 系统通知、DSH 告警列表和持久日志，输出恢复后清零并停止提醒。这条完整路径不需要 JEV，成为后续异常结束和语义告警共用的观察与呈现能力。

实施须等待用户明确恢复开发。只检测、通知和记录；修改留在自研插件和项目集成层。

## 验收标准

- [ ] 监控经项目既有装配方式进入 DSH，通过原生 Agent 公开生命周期和模型流事件观察主代理及原生子代理，包括原生 spawn/fork、Team 和 Owner 路径；第三方 LLM 服务不改变监控身份。
- [ ] 检查间隔默认一分钟、连续无输出阈值默认五次，两者可经监控设置分别调整。仅对仍在等待模型输出的请求计数，包括尚未产生首段输出的请求。
- [ ] 验证默认时间线：第五分钟有输出，第六分钟计一次，第十分钟告警，第十一分钟继续告警，第十二分钟输出后清零。达到阈值后的每轮继续提醒，仅去重同轮重复事件。
- [ ] 新增正文、思考文字和工具调用参数分别清零；网络心跳和仅更新用量统计不能清零。每个代理、每个请求独立计数，其他代理的活动或旧请求的计数不影响新请求。
- [ ] 已结束模型请求后的长工具执行、等待审批、等待用户输入和空闲不累计模型无输出；主动取消不作为代理失败。
- [ ] 实际告警包含代理与请求标识、类别、时间和原因，出现在 DSH 列表与持久日志并提交 macOS 通知。恢复只更新状态和记录恢复时间，不发恢复弹窗。
- [ ] 默认日志只记录元数据与错误原因，不记录会话片段；密钥和认证请求头始终不进入日志或状态。不开启任何自动取消、重试、换模型或代理干预消息。
- [ ] 通过真实 Host 和公开模型流模拟验证默认及自定义计数、状态隔离、正常等待、恢复和同轮去重；正常任务仍能完成且无 JEV 也能告警，不调用付费模型。系统通知提交与实际操作系统送达分别记录验收证据，实际送达采用 macOS 人工验收。

## 被什么阻塞

无，可立即开始。此处表示没有工单前置依赖；代码开发仍受用户暂停指令约束。
