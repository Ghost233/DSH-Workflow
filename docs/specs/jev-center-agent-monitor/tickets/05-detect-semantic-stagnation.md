## 父项

[Spec #12：统一 JEV 中心与 DSH 原生代理监控（仅检测）](https://github.com/Ghost233/DSH-Workflow/issues/12)

## 要构建什么

用户在监控设置中选择一个调用模型名，供主代理和子代理共用。当模型仍持续思考却没有正文或工具调用进展时，监控通过 JEV 中心判断是否疑似停滞；连续明确异常才告警，并允许用户控制调试片段记录。JEV 判断未知或失败时只显示判断不可用，确定性监控继续。

实施须等待用户明确恢复开发。所有语义判断均用于检测，不能转换成代理执行指令。

## 验收标准

- [ ] 用户在监控设置中选择调用模型名，主、子代理均经中心请求同一名称，不在监控中重复配置 URL、密钥或上游传输。单套有效配置即可完成本工单。
- [ ] 请求仍在持续思考且没有新增正文或工具调用进展达到默认三分钟后开始判断，此前不请求 JEV，之后沿用监控检查间隔。起始等待时间可配置；正文或工具调用进展结束当前停滞窗口，请求结束后停止判断。
- [ ] 思考文字能清零无输出计数，但自身不能当作正文或工具调用进展关闭语义检测；语义与无输出计数相互独立，主、子代理及各请求的语义状态隔离。
- [ ] 连续明确语义异常默认五次才告警，该阈值独立可配置。达到阈值后每个检查轮次继续提醒，同轮去重；明确正常或实际进展后停止当前持续提醒并记录恢复，不另发恢复弹窗。
- [ ] 明确正常、未知结果或失败均清零语义异常计数。未知或失败显示判断不可用，不计为代理卡死、不记录代理恢复；缺失、停用及请求错误在界面显示红色引擎不可用状态及具体原因，不能笼统当作“引擎缺失”。
- [ ] 引擎故障不发系统通知。JEV 的五秒默认或自定义超时不阻断代理流，确定性检测仍工作，不重试、不换配置、不取消或干预被监控代理。
- [ ] 语义监控告警通过已建立的通知、DSH 列表和持久日志呈现，记录判断概率、耗时、元数据及错误原因；不添加未经验证的固定概率阈值或准确率承诺。
- [ ] 提供默认关闭的调试片段记录开关，关闭时不将会话片段落盘，开启后才记录用于排查的片段。两种状态下密钥和认证请求头都不入日志、错误或界面。
- [ ] 通过真实 Host、公开原生 Agent 事件和模拟 System One 上游验证启动等待、逐轮调用、异常阈值、正常/未知/失败重置及设置变化；无付费模型调用，正常任务和确定性监控在 JEV 失败时仍可推进。
