## 父项

[Spec #12：统一 JEV 中心与 DSH 原生代理监控（仅检测）](https://github.com/Ghost233/DSH-Workflow/issues/12)

## 要构建什么

用户在 DSH 标准设置和凭据管理中配置一套 JEV 引擎配置，保存后可主动测试连接；消费插件通过调用模型名向统一 JEV 中心请求判断并取得结果。这张工单交付一套配置从保存、凭据解析、System One 请求到可见测试结果的完整路径，为后续多配置和语义监控提供可复用入口。

仅准备及发布工单不恢复父规格中暂停的代码开发；实施须等待用户明确恢复开发。修改留在自研插件和项目集成层。

## 验收标准

- [ ] 用户可以通过 DSH 标准 Settings 保存 URL、上游模型名、调用模型名、启用状态和请求超时；密钥通过标准 credentials 管理，普通配置只保存凭据引用。
- [ ] 调用模型名默认沿用上游模型名，也可自定义。消费方指定调用模型名，中心请求携带实际上游模型名；只使用 TypeSafe 官方 `/v1/systemone` 兼容协议。
- [ ] 保存配置不发起模型请求。“测试连接”使用固定小型判断题，经同一中心请求路径展示成功或错误、实际返回模型版本和耗时，不发送代理会话内容。
- [ ] 消费方通过公开的命名调用入口得到判断结果或明确错误；没有全局唯一“当前引擎”，消费方无需另配 URL、密钥或上游协议。
- [ ] 请求超时按配置生效，默认五秒。缺失、停用、鉴权失败、服务错误、无效判断和超时均有明确结果，不自动重试或切换配置，超时只作用于 JEV 请求。
- [ ] 密钥和认证请求头不出现在普通配置、连接测试结果、错误展示及日志中。沿用 DSH 凭据机制，不额外迁移到操作系统钥匙串。
- [ ] 自研中心经项目既有装配方式进入 DSH；在真实 Host 中通过公开配置、凭据、中心调用与模拟上游验证上述路径，不修改 DSH 或第三方插件源码，不调用付费模型。

## 被什么阻塞

无，可立即开始。此处表示没有工单前置依赖；代码开发仍受用户暂停指令约束。
