## 问题陈述

用户通过 DSH 原生代理使用第三方模型服务时，可能遇到连接仍在、模型却长时间没有输出，模型流突然中断但界面没有明确反馈，或持续输出思考文字却没有实际进展的情况。主代理和子代理均可能出现这些问题。用户无法实时盯着每个代理，因而可能在数分钟甚至更长时间后才发现任务停滞。

测试阶段尚未确定可靠的自动处理方案。用户需要检测、通知和原因记录，以便自己判断下一步，不能因为监控判断而自动中止、重试或切换模型。

同时，不同插件可能需要使用不同 JEV 服务或判断模型。若每个插件分别配置 URL、密钥和上游协议，配置会重复且难以统一管理。用户需要一个 JEV 中心，允许多套 JEV 引擎配置同时启用，消费插件通过调用模型名选择所需配置。

## 解决方案

增加两个自研插件：JEV 中心管理引擎配置与命名调用；代理监控插件观察 DSH 原生主代理和子代理的公开事件，独立累计无输出次数、记录异常结束，并通过 JEV 判断持续思考是否疑似停滞。

用户通过 DSH 标准 Settings 和凭据管理配置 JEV 服务，保存多套配置并分别启用。调用模型名默认沿用上游模型名，也可以命名为 quick、full、hard 等；消费插件指定调用模型名，中心按对应配置完成 TypeSafe System One 请求并返回结果。

代理监控默认每分钟检查一次。同一被监控请求连续五次没有模型输出活动时开始告警，此后每轮仍无输出就继续提醒，恢复输出后清零。持续思考三分钟且没有新增正文或工具调用进展时开始语义检测，连续五次明确语义异常才告警。时间和次数均按下文分别配置。

实际监控告警通过 macOS 系统通知、DSH 内告警列表和持久日志呈现。JEV 无法调用时，界面显示红色的 JEV 引擎不可用状态及具体原因，由用户手动排查；确定性检测继续工作，正常代理流程继续运行。

## 实现决策

- **模块职责与架构。** 遵循已接受的 ADR《用统一 JEV 中心按名称调用多套引擎配置》。JEV 中心独立管理配置、解析凭据、调用上游和返回结果；代理监控负责观察、计数、判断调度及告警呈现。消费插件不各自维护 JEV URL、密钥和上游传输逻辑。不存在全局唯一“当前引擎”。
- **标准配置与凭据。** 使用 DSH 公开的插件配置、Settings 和 credentials 接口。普通配置保存服务 URL、上游模型名、调用模型名、启用状态、请求超时以及凭据引用；实际密钥交由 DSH 凭据系统管理。不能把 DSH 标准本地凭据存储描述为操作系统钥匙串，也不能把 JEV 当成普通聊天模型提供方配置。
- **协议与调用契约。** 只支持 TypeSafe 官方 System One `/v1/systemone` 兼容协议。消费插件提供调用模型名和符合该协议的判断请求内容；中心唯一解析已启用配置，使用其中的上游模型名发起请求，并返回判断结果或明确错误，以及可用于展示、记录的实际模型版本和耗时。调用模型名仅作路由，不表示推理强度。
- **命名与启用。** 调用模型名默认等于上游模型名，允许自定义。已启用配置之间的调用模型名必须唯一，重名时拒绝冲突的启用状态并提示改名，不能静默选第一套。不同配置的上游模型名可以相同。
- **连接测试。** 保存配置不发出模型请求。独立的“测试连接”操作使用固定的小型判断题，通过同一 System One 请求路径验证配置，展示成功或错误、实际返回的模型版本和耗时，不发送代理会话内容。
- **配置生命周期。** 请求开始时固定其所用配置，已发出的请求按原配置完成或超时，后续修改只影响新请求。允许停用或删除消费插件正在引用的配置；后续调用明确不可用，消费插件显示原因。在途请求仍遵循原配置规则。删除引擎配置不自动删除 DSH 凭据。
- **请求失败与超时。** 每套引擎配置的请求超时分别可调，默认五秒。配置缺失、停用、鉴权失败、服务错误、超时或无法得到有效判断时，返回明确错误；不自动重试，也不自动改用其他配置。超时只作用于自身 JEV 请求，不能中止被监控代理。
- **监控对象。** 通过 DSH 原生 Agent 的公开生命周期和模型流事件监控主代理及原生子代理，包括普通 spawn/fork、使用原生 Agent 的 Agent Team 成员。第三方 LLM 服务不改变其 DSH 原生代理身份；每个代理、每个被监控模型请求分别维护观察状态，新的请求不能继承上一请求的计数。
- **无输出检测。** 仅对仍在等待模型输出的请求累计连续无输出次数。正文、思考文字或工具调用参数的新增属于模型输出活动，发生后立即清零并停止相应持续提醒；网络心跳和仅更新 token 用量统计不清零。其他代理的输出不影响当前请求。模型请求已结束后的工具执行、等待审批、等待用户输入和空闲状态不作为模型无输出；主动取消不作为代理失败。
- **无输出时间线。** 默认每一分钟检查一次，连续五次没有模型输出活动时告警。若第五分钟仍有输出，第六分钟为第一次无输出，第十分钟为第五次并告警，第十一分钟仍无输出则再次告警，第十二分钟出现输出则清零。达到阈值后的每个检查轮次均可再次提醒，仅去重同一轮的重复事件，不能用“一次告警后永久静默”替代该规则。
- **异常结束检测。** 根据公开模型流和代理终态事件记录真实错误、能够证实的异常中断、空结果或缺少正常结束标记的 EOF、输出限制导致的未完成等情况，保留接口提供的原因并告警。不能宣称从一个被上游正常结束标记包装的部分回答中必然推断出隐藏故障。所有处理均为观察，不改变原请求终态或重试策略。
- **语义检测调度。** 监控设置选择一个调用模型名供主代理和子代理共用；其他消费插件可同时调用中心的其他名称。仅当模型请求仍在持续思考、连续三分钟没有新增正文或工具调用进展时开始语义检测，后续沿用统一检查间隔。正文或工具调用进展结束当前停滞窗口；思考文字虽能清零无输出计数，本身不等于已经取得正文或工具调用进展。
- **语义检测结算。** 明确语义异常连续五次才告警，达到阈值后按检查轮次持续提醒。明确正常，或未知结果、请求失败时清零语义异常计数。未知或失败显示 JEV 判断不可用，不表示代理恢复；不能把请求错误计为语义异常。正常进展或请求结束后停止当前持续提醒。判断概率用于记录，规格不设定未经验证的固定概率阈值，也不承诺语义判断零误报。
- **可配置参数。** 检查间隔默认一分钟；连续无输出次数默认五次；语义检测起始等待时间默认三分钟；连续语义异常次数默认五次；每套 JEV 引擎配置的请求超时默认五秒。无输出与语义异常次数是独立参数。调试片段记录默认关闭。
- **告警与恢复。** 实际监控告警同时进入 macOS 系统通知、DSH 内告警列表和持久日志，能识别对应代理、请求、告警类别、观察时间和原因。恢复仅更新对应状态并记录恢复时间，不另发恢复弹窗。重复提醒遵循逐检查轮次规则，同轮重复事件不产生重复告警。
- **引擎不可用。** 缺失、停用或无法完成请求时，在界面显示红色的 JEV 引擎不可用状态及具体原因；只有配置确实缺失时才显示“引擎缺失”。引擎故障不另发系统通知，由用户手动排查。确定性无输出和异常结束检测继续，不能据此修改或阻断代理正常流程。
- **日志边界。** 默认持久化元数据、判断概率、耗时和错误原因。仅用户开启调试片段记录后才将调试会话片段落盘。无论是否调试，密钥和认证请求头始终不进入日志、普通配置或状态展示。
- **项目集成边界。** 两个自研插件通过项目既有插件装配方式进入 DSH 正常流程，调用者使用既有日常启动入口。兼容与接线修改留在自研插件或项目集成层，DSH 和第三方插件源码保持上游原样。引擎配置问题不会转换成主代理提示词或工作流干预。

## 测试决策

测试沿用用户已经接受的范围：通过 DSH 公开模型流和代理事件模拟无输出、异常结束及语义停滞，验证主代理和子代理分别记录，并覆盖长工具执行与正常等待不误报。不再为规格开启新的访谈。

优先复用一个高层接缝：真实 DSH Host 装配自研 JEV 中心和代理监控插件，经公开配置、凭据、命名调用及原生 Agent 事件驱动，检查可见状态、通知提交和持久记录。上游模型与 JEV 服务在网络边界模拟，使用可控时间验证计数，不调用付费模型。已有原生 Agent 流模拟和真实 Host 装配验收可作同类范例；不直接测试内部计数函数、私有状态或具体实现结构。

验收覆盖以下外部行为：

1. 保存多套引擎配置、同时启用不同调用模型名，经不同消费方正确路由；自定义调用模型名不改变发往上游的模型标识。
2. 启用重名配置时明确拒绝冲突；配置缺失、停用、错误凭据、上游错误及超时分别返回明确原因，不重试、不切换到其他配置。
3. 标准配置与凭据分开管理；保存不请求上游；连接测试使用固定小判断题，展示实际结果、模型版本和耗时，未发送代理会话。
4. 在途请求期间修改、停用或删除配置，当前请求仍按原配置完成或超时，新请求使用新配置或明确不可用；删除配置未删除凭据。
5. 默认无输出时间线逐轮验证第六分钟计一次、第十分钟告警、第十一分钟再次告警、第十二分钟输出后清零；更改检查间隔与阈值后遵循所配值。
6. 正文、思考文字、工具调用参数新增分别清零；心跳和用量统计不能清零；同轮重复事件去重，跨轮持续无输出继续告警。
7. 主代理、原生子代理及连续模型请求之间状态隔离；某个代理有输出不能清零其他代理的计数，结束后的新请求不继承旧计数。
8. 长工具执行、正常审批或用户等待、空闲和主动取消不被归为模型卡死；模型尚未输出任何内容的等待请求仍可按规则被检测。
9. 模拟真实错误、异常流中断、空或未标记正常结束的 EOF、明确未完成终态，验证原因记录和告警；正常完成不会被当成异常结束。
10. 思考持续但没有正文或工具调用进展时，起始等待时间前不调用 JEV，达到等待时间后按检查间隔调用；正文或工具进展后停止当前停滞窗口。
11. 连续明确语义异常达到独立阈值才告警，之后每轮继续提醒；明确正常、未知或失败分别清零。未知或失败仅显示判断不可用，不记录为代理已恢复。
12. JEV 不可用时出现红色状态和实际原因，未产生引擎故障系统通知；同一 Host 内确定性检测仍可告警，代理流仍正常推进。
13. 实际监控告警出现在 DSH 列表、持久日志和 macOS 通知提交边界；恢复更新状态和时间但不产生新的弹窗。操作系统实际送达在 macOS 人工验收中另行确认，不能以模拟通知提交代替。
14. 默认日志无会话片段，启用调试后才记录片段；所有日志、状态与普通配置均不含密钥或认证请求头。
15. 观察到告警、JEV 超时或引擎不可用后，监控未取消、重试、切换模型或向代理发送干预消息。正常任务在装配监控后仍能够完成。

好的测试以用户能观察到的结果与公开请求契约为断言，能暴露错误路由、错误计数、等待误报和监控越权。已有原型测试通过不等于本规格实现完成，新增中心配置和已修订计数规则必须重新按本规格验收。

## 范围之外

- 自动中止、重试、换模型、恢复代理、发送提醒提示词或任何会改变任务执行的处理策略。
- 外部 CLI、ACP、专用 SDK 等另一套代理系统的进展桥接。它们不等于使用第三方 LLM 服务的 DSH 原生子代理。
- OpenAI Chat、Responses、OpenRouter 等其他 JEV 传输协议适配，以及全局唯一“当前引擎”或故障后的备用引擎自动切换。
- 上下文压缩或裁剪、修改 billion-context、其他第三方插件或 DSH 上游源码。
- 操作系统钥匙串迁移、重做 DSH 凭据系统、引擎健康自动修复或独立巡检平台。
- 保证所有停滞都可识别、保证语义判断无误报，或根据本次设计宣称真实生产准确率与性能收益。
- 本次规格发布时恢复代码开发、构建新启动器、切换或重启运行中的 DSH 服务。
