# Browser Harness 内部插件

## 交付范围

用户于 2026-10-23 调用 spec-delivery，要求交付已讨论的 Browser Harness 内部插件。起始分支为 main，基准提交为 `19cad95ef6714a33ccf034f987d859c4fdfcfbac`。设计来源见[访谈](../../analysis/2026-10-23-browser-harness-plugin/design-interview.md)和 [ADR-0011](../../adr/0011-browser-harness-build-time-skill-check.md)。

内部插件独立记录版本，通过 `vendor/browser-harness` 子模块固定官方上游。首个基准为已调研的 `c6a941287424f32e2d20c7b7b892c8493f46808d`。官方 Skill、安装说明和配套参考文档保持原文，随应用交付；项目技能入口指导 DSH 读取这些本地资料。

## 验收要求

1. 打包核验子模块实际提交等于主仓库 gitlink，拒绝未初始化、偏离或修改的输入。包内记录插件版本、上游完整提交、官方版本和所选文件摘要，移到另一目录仍能加载技能和参考文档。
2. 打包时比较上游技能资料，只报告变化，不推进子模块。无法访问上游时明确报告检查失败，继续使用已核验的固定内容；固定内容自身校验失败则停止打包。这项失败策略采用此前推荐方案，随本次交付公开记录。
3. DSH 原生代理可发现 Browser Harness 技能，使用 CLI 操作并验证结果。原版资料中浮动的在线链接由项目入口指向随包的固定资料，不修改上游文件。
4. 插件通过当前 DSH Shell 查询 `browser-harness` 的可执行路径与版本，关闭该次查询的遥测。查询不连接 Chrome、不截图、不执行浏览器任务、不安装或升级软件。
5. 启动器现有版本列表展示内部插件、技能基准和本机 CLI 状态。复用现有列表读取流程，不新增按钮、DSH 管理页、轮询或在线更新。DSH 未运行、插件不可用、命令缺失和版本执行失败均显示真实状态，不从其他环境推断成功。
6. 日常启动仍为无参数 `./start-dsh-workflow.sh`。保留现有项目插件、用户停用选择和服务生命周期。未经授权不切换现有服务或正式发布。

## 公共验证入口

- 技能与打包入口：验证固定输入、摘要、完整文件和搬迁后读取，覆盖上游变化及访问失败。
- 插件只读查询：以受控可执行程序验证真实路径、版本、缺失、失败和遥测关闭，再通过真实 DSH 服务验证方法装配。
- 启动器版本报告：验证本机结果来自 DSH、不可达时不误报，以及现有行和设置保持不变。

项目完整门禁沿用 `node scripts/run-project-tests.mjs`、客户端构建检查和发布流程的本地回归。修改 Flutter 时运行其格式、分析及受影响测试；必要的实际技能加载与只读版本查询使用隔离测试资源完成。
