## 问题陈述

工具维护者同时维护 MacLauncher 管理端和 DSH 启动器，使用者需要统一入口、独立启动、既有配置和共享 Desktop 后端。Flutter 迁移已经先行实施，需要以正式规格、既有九张 Ticket 和逐故事证据判断交付状态。

用户现已明确将 macOS 构建与分发收敛为 Apple Silicon（ARM64），删除整个旧自研编排机制及其相关代码和当前文本，并保留独立 JEV 中心和 DSH 原生代理监控。当前版本应落实这一维护边界，同时保持 SDK、窗口、焦点、权限、插件和真实 Release 验收要求。

## 解决方案

Flutter 负责启动器管理界面与应用侧控制，直接使用官方纯 Dart MacLauncher SDK。DSH-Workflow 与 MacLauncher 保持独立仓库、构建和分发，官方 DSH、SDK 和其他上游源码保持原样。

MacLauncher 管理端管理 Web 访问服务、观察 Desktop 后端、打开管理窗口并协作入口接管。DSH 启动器独立持有自己的 Web 访问资源；官方 Desktop 独立持有 DSH 后端。管理端缺席、断线或入口归还不结束业务。

项目移除旧自研工作流机制，独立装配保留的 JEV 中心、DSH 原生代理监控及 Matt 派生面板。JEV/监控迁入独立自研模块，保持现有命名调用、标准配置/凭据和原生事件观察功能，不扩展新的代理系统或后台架构。

## Desktop窗口与启动可见性

1. 后台启动：未运行时启动并隐藏；已运行时复用同一Desktop，不能自动隐藏使用者正在用的窗口。
2. 启动后显示：未运行时启动并显示/激活；已运行时显示/聚焦同实例。
3. 隐藏窗口：只隐藏正在运行的窗口，Desktop、Host、Web及业务继续。
4. 仅显示已运行窗口：只显示/聚焦现有实例；未运行时明确提示，不隐式启动。

持久化“启动时隐藏窗口”，缺值默认false。常规与登录启动遵循该项，已有Desktop保留当前窗口状态；显式“启动后显示”或“打开DSH”优先显示。此子项继续映射故事5/9/10/11/20/23/26/28，由T02/T05/T07/T09承接；Command+Q/退出快捷键不扩展本次范围。

ARM64实际验收记录首次窗口、隐藏/activation、Host/Web/SDK真实ready、运行中同Host/租约、保存重启、已有窗口不隐藏及显式找回。接受官方首次window.show短暂显示/activation，但最终必须同一物理Desktop hidden=true、onscreen=0、Host/Web/SDK ready，并恢复真实原前台焦点；如实记录观察限制，不承诺整个启动零激活、精确持续时间或未来不闪窗。不使用hidesOthers，不以OpenConfiguration或SDK成功代替物理结果。

外部应用前台经正式SDK冷启动时，成功前以只读OS当前输入计数、原生新读与物理身份确认真实baseline及最终前台。未知或输入干扰不记通过，也不强夺使用者的新选择；合法无recovery事件可在已知当前计数相等且最终状态正确时通过。

## 保留模块的独立归属

JEV中心和DSH原生代理监控位于独立自研模块 `agent-observation-plugin/`，固定profile ID `workflow-jev-center`、`workflow-agent-monitor`保留，配置与命名调用继续兼容；主/子代理监控只检测、记录、通知，不中止、重试、切换模型或发送干预。DSH原生“设置”/“插件”入口仍可管理两模块，不依赖被删仪表盘或运行机制。

领域行为沿用[正式Spec #12](https://github.com/Ghost233/DSH-Workflow/issues/12)和已接受的JEV命名配置决策；本规格新增的是迁出、独立装配和分发保持要求，不新增传输协议、全局唯一引擎、自动恢复或OS通知送达承诺。配置/凭据分离、引擎不可用不阻断确定性监控及DSH代理流程继续保留。
