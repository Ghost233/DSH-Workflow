## 已准备的源码

`lib/lifecycle_probe_process.dart` 是 Debug 外部 I/O 接缝。它先调用真实 `Process.start`，再在已隔离 native test profile 且存在显式 gate 环境变量时记录实际 child PID。仅当 `.arm` 文件存在才通过私有 Unix socket 暂缓交付进程句柄，直到收到完整 `release` 行；没有模拟 Web、Host、SDK、native 或 controller 私有状态。闸门异常只对该函数产生的实际 child 发送 SIGKILL。`main.dart` 仅在 Debug 注入此适配器；Release 仍采用原有默认 Process.start。

`LauncherController._close` 只增加 Debug + 隔离 profile + gate 条件下的 `lifecycle-close-started` 文件事件，用于证明真实 close 已开始后才放行晚到句柄。没有修改 `_mutate`、启动晚句柄的终止等待、`_stopWeb`、`restartWeb`、child exit 结算或 native 退出顺序。源码里晚句柄分支的普通终止信号与无界 `exitCode` 等待目前仅是待复现风险，不能写成已确认产品缺陷。

`lib/application_probe.dart` 让 Debug 驱动释放 semantics 句柄最多一次，使第二次真实 quit 能抵达原有 native 路径。此项是未验证的驱动准备，不是已验证的产品重复退出修复。

单个 `tool/lifecycle_application_scenario.dart` 接在 T03 的共享 WebObservation hook 后。当前只准备 `late-handle-paused-quit` 一个垂直场景：先经真实 UI 启动并认证 Web，再正式 SDK 回收；下一次 UI 启动产生真实进程并由外部闸门暂缓句柄。正式 SDK 回收在管理端会话重建前后均须报告准确 busy；场景保留 SDK 原始脱敏错误、实际 Host PID/lease 与 held child PID，使用实际截图作为辅助观察。随后只暂停该自有 child，重复发出真实 native quit，观察 close 开始事件，再放行句柄并检查退出结果。

`tool/application_probe.dart` 仅增加选项、隔离 gate 环境和单场景分派。`tool/web_application_scenario.dart` 复用既有 headless Host 启动块，并给共享 observation 提供自有 Host 的 IPC shutdown / replace 闭包。replace 后直接 Host health 的地址与认证 cookies 从实际新 receipt 刷新；正式 SDK 仍每次使用当前真实管理会话。实际 Host 退出/新 lease 的后续恢复场景尚未写成或执行，不据此勾选验收项。

## 待执行的红绿与清理准则

许可后先完成必要工程检查、Debug 构建和应用关联装配，冻结 source commit、实际候选路径及 payload SHA，再在主线程给定时段运行计划中的原固定场景。首次原始错误、退出码与资源事实必须保留；先区分驱动、工程环境、上游 Host 清理与本项目生命周期失败，然后只对真实确认的本项目缺口作最小修复，同一命令取得真实 green。

晚句柄场景成功须同时满足：启动尚未取得句柄时两次正式 SDK 回收均准确 busy；重复 quit 共用结算；放行后 Launcher 正常退出 0；该实际 Web child PID 明确不存在；真实 ServerSocket bind/listen 访问端口成功；独立官方 Host 的认证 health 仍返回原真实 lease。不能以 VM/native action 回执、进程 Gone、receipt 删除或单独 bind 成功替代全部事实。

失败清理只恢复并终止本场景记录的暂停 child，关闭私有 gate；共享应用驱动清理 Launcher，Host helper 通过实际 IPC shutdown 并严格要求正常退出。Headless Host 的 10 秒兜底 SIGKILL 不能冒充正常退出或产品 green。全过程不按名称、Bundle ID 或用户端口杀进程，不能修改上游或冻结资源。

T03 已协调 child-exit tail drain 接口：实际 exitCode 到达与 stdout/stderr 消费完成是两个阶段；未来产品修复应先取消 observer、结算 pending control 请求，再等两个消费者 drain，最后清 child 身份。状态不能在已退出的 control 通道上继续查询。这些均为待实测后的方案，本阶段未实现。T03 的日志来源/UUID/cache 改动、T05 的设置/password 改动保持各自所有权。

全部本票验收标准仍待实际证据，包括真实 Host 退出/新 lease 后 UI 与 SDK 恢复、共享互斥、并发资源唯一性、正常与启动中退出、暂停 child 端口释放及独立 Host 生命周期。源码准备提交暂不集成 canonical、不 push、不关闭 #5；收到工程初始化许可后继续真实 TDD。
