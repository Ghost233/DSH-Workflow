## 变更与完整应用边界

唯一产品生命周期修复在 `LauncherController`：句柄晚于 close 返回时，复用原 `_stopWeb` 已有的 3 秒 SIGTERM → SIGKILL 终止流程，确认实际 exit 并消费完该未交付 child 的 stdout/stderr。`_stopWeb` 仅调用同一 helper，原超时不变。没有因为源码风险扩改 `_mutate`、正常 child-exit/日志消费、状态查询或 main 的退出顺序；真实验收已确认这些既有互斥与正常回收行为。

Debug 接缝 `lifecycle_probe_process.dart` 先调用真实 Process.start，再仅在 Debug、native 隔离 test profile 与显式 gate 环境成立时记录实际 PID。外部 Unix I/O gate 的 arm/release 暂缓真实句柄交付，没有模拟业务、Host、SDK、native 或私有 controller 状态。close-started 文件只观察真实 close 已开始。重复 quit 的 Debug 驱动释放 semantics 句柄最多一次。Release 保持原默认 Process.start。

单个 `lifecycle_application_scenario.dart` 复用 T01/T02/T03 的真实 main、Swift Runner、语义动作、正式 MacLauncher SDK 与 WebObservation，不复制驱动/管理端宿主。headless 官方 Host 使用不可变 packaged 业务代码和真实 IPC；停止/替换 helper 只管理本场景创建的 Host，替换后从新 receipt 刷新直接健康 URL/cookies。业务 lease、Web connection UUID、健康 ready、PID 和监听者均读取实际来源。没有按测试意图填写 UUID 或时间、修改第三方或上游。
