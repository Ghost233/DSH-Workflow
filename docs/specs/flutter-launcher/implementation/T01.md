日期：2026-10-06。分支：`codex/flutter-launcher-t01`。规划基点：`b1321cfa78b8927f6e92a75ec772027dfd039722`。实现候选：`233ccc8cbffb92ad95cca734768446a71519c115`（包括前序 `f1fd31aa92a4839c86a4bdb57bcc7c367f56387b`）。

## 实现与接缝

保留真实 `main()`、LauncherController、官方 MacLauncher SDK 和 Swift Runner。仅 Debug 隔离模式注册应用探针；它读取真实 Flutter 可访问性树，按当前 RenderView 的正式 semantics action 操作控件，不读取 Widget callback 或直接调用 controller。原生关闭使用 `performClose`，自己的入口使用真实菜单项 `NSApp.sendAction`；SDK 的 openWindow 调用真实窗口桥。

Debug 测试 root 使用独立偏好文件、DSH home、资源目录和 SDK socket，空密码不回落旧钥匙串，登录项查询/变更不访问系统状态。测试重开通知按测试 root 隔离，避免激活当前生产启动器。普通 Debug 与 Release 的数据、偏好、密码和 SDK 解析保持原有生产路径。

实例认领现在在 `MainFlutterWindow` 创建 `FlutterViewController` 前完成。第二进程只通知并激活既有实例，不能先启动 Flutter/Dart 或密码触发的业务工作。重开通知立即交付，标准 macOS reopen delegate 也激活原窗口。

管理端验收宿主使用固定官方 `launcher_core` 的真实 ProjectManifest、BindingStore、LauncherServer、EntryLauncher；它是外部工具的 dev dependency，未进入生产应用入口。管理端核心和应用 SDK 均解析到 `bc7262f4047e81f55922c203948ac64d9e0e2d13`。SDK 的 hosted 约束通过项目侧同一 Git 提交 override 解析，lockfile 由实际 pub get 生成，未修改上游。

探针启动前只读验证项目 bundle ID、Debug kernel、原生隔离桥及 Dart driver 标记；Xcode 的相邻 `.debug.dylib` 也参与桥验证。Release/未知候选在复制、签名和启动前拒绝。有效输入先用 ditto 复制到探针自有 root，再只修改/重签该副本。LaunchServices 不继承直接启动进程的环境，因此私有 Debug 副本携带 `DSHLauncherTestRoot`，使正式关联 reopen 仍使用同一隔离 root/socket。构建源 Info.plist 不含此键，Release 不解释它。
