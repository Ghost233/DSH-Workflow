## 实现与公共接缝

正常运行时子进程的 `DSH_HOME` 固定为原生解析的 home，NSWorkspace 打开新 Desktop 时显式传递同一 home 与权限模式。生产路径仍优先复用已有 Desktop，Web 仍只拥有访问监督进程和认证网关。

Debug 隔离模式打开 Desktop 时限定新实例、准确应用 URL、私有 Electron userData、更新记录及诊断路径，并观察实际返回的 Desktop PID。只有 Debug 隔离应用读取测试端口；运行时 CLI 将选定端口沿原有 `startGlobalSupervisor` 入口传递，普通应用保留 33080。

复用 T01 同一个真实 `main()`、Swift Runner、Flutter 可访问性树和固定官方 MacLauncher SDK。`tool/application_probe.dart` 只新增选项、资源 stage 和独立 Web scenario 接点；没有复制另一套 VM/native/管理端宿主。`tool/web_application_scenario.dart` 使用真实 UI semantics 输入密码与启动/停止控件，以及官方 `launcher_core` 的 BindingStore、LauncherServer、真实 session；不直接调用 LauncherController。密码语义值在 Debug 响应中遮蔽。

headless 模式通过真实 IPC 运行不可变 packaged `@deepseek-ai/dsh-desktop-host`，准备过程只使用项目侧集成层和私有 profile。它是已有真实后端的补证，**不证明 NSWorkspace → 官方 GUI → Host 打开路径**。Desktop GUI 模式在非 GitHub CI 中于任何复制、签名或应用启动前明确拒绝。

## CI 交接

在干净的 GitHub macOS runner 中构建、装配同一候选及正式 packaged resources 后运行：

```sh
dart run tool/application_probe.dart 'DEBUG_APP/Contents/MacOS/DSH Workflow' --web-runtime 'PACKAGED_APP/Contents/Resources' --web-backend desktop --web-port 33080
```

这是路径占位的执行形状，主线程须在 CI 中绑定实际路径和完整 commit，再作为固定命令执行。本模式从没有 receipt 的状态，经真实管理窗口设置隔离密码并启动 Web；其余 UI/SDK 两入口、顺序复用、认证与回收场景与本地共用。它额外要求 receipt 的 Host 是 NSWorkspace 打开之 Desktop 的子进程，profile/userData 确在私有路径，最后通过该 tracked Desktop 的正常 native terminate 路径清理。

当前没有 GitHub 操作、推送、服务切换、Release 发布或上游修改。整票只在上述未结验收有真实证据后完成。

快速 CI 可以只读复用成功分发 run `37325723931` 的 matching-arch `dsh-workflow-arm64` / `dsh-workflow-x64` DMG artifact：`hdiutil attach -readonly -mountpoint "$RUNNER_TEMP/runtime-mount" ARTIFACT.dmg`，资源根为 `"$RUNNER_TEMP/runtime-mount/DSH Workflow.app/Contents/Resources"`。当前 commit 的 Debug build 单独复制为 candidate，仅写当前关联 manifest；探针内部 overlay 当前项目 runtime 脚本。主线程须记录 artifact 来源 commit、下载文件 SHA、实际挂载/候选路径和完整测试退出证据，最后正常 detach。这是当前启动器与 runtime 控制层搭配冻结业务产物的验收；**不替代 T09 对当前 candidate 的全量 arm64/x64 分发构建**。
