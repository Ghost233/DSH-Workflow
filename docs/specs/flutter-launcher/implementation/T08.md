## 真红 → 最小绿

1. 一个已安装的受控自研插件 manifest JSON 损坏，`checkPluginVersions` 整体抛出 `SyntaxError`，健康插件已完成的结果丢失。红命令 raw exit 1。最小修复在该 profile dependency 的 manifest 读取边界追加 error 行，并继续其他项；未知当前/兼容版本如实为无法读取，检查不修复包源。新测试及既有测试共 12 项通过，raw exit 0。
2. 默认 Desktop 更新器调用通用 DSH CLI，真实返回 `profile "desktop" is managed exclusively by the Electron application`，raw exit 1。最小修复让 Desktop 更新走项目已有 `run-dsh.mjs`，只对精确 `plugin --profile desktop` 调用官方公开 `runCli({manageDesktopProfile:true})`。Web 更新保留既有通用 CLI 路径。真实打包 DSH/pnpm 下载自研 tarball，实际版本从 1.0.0 变为 1.1.0，raw exit 0。

## 待执行边界与工程依赖

Flutter 工程初始化许可仍待用户明确回应。T08 未执行 pub get、缓存复制、远程 CI、替代 SDK、format/analyze/build 或 GUI；不会借用其他 worker 的已初始化 GUI 槽。后续必须在正式许可和独占 GUI 槽就绪后编译候选，并运行既有应用驱动及本票场景。

窗口待验证疑点：`checkPlugins` 汇总未标注按项检查失败数量；`updatePlugins` 未使用 failedChecks，后续空更新会清除 pluginsNeedReload。它们目前只是源码疑点，尚未有真实窗口红证据，因此本阶段不改产品 UI/controller。

生产 checker 的 npm registry fetch 固定为 `https://registry.npmjs.org/`。标准 pnpm registry/userconfig 足以使默认更新器使用自有 registry，但不会改变 checker fetch；Node fixture 的成功不是完整管理窗口版本检查证据。完整应用更新场景需要在进程外控制实际 HTTPS registry 响应，或者使用已真实发布的受控自研版本，不能猴子补 fetch、替换安装器或增加只为测试的通用生产配置。

最小外部网络方案调查：打包 Node v24.21.0 的 `--help` 列出 `--use-env-proxy` 和 `NODE_EXTRA_CA_CERTS`；独立 loopback proxy 探针已确认 `NODE_USE_ENV_PROXY=1` + `HTTPS_PROXY` 使真实 Node fetch 发出 `CONNECT registry.npmjs.org:443`，由该自有 proxy 主动拒绝（该 fetch exit 1，能力探针 exit 0）。后续可用 private tmp 的临时自有 CA、仅接受 registry 主机的 loopback TLS proxy 和自有 tarball fixture；`NO_PROXY=localhost,127.0.0.1` 保持真实 Host 直连，不改系统 trust/DNS。TLS证书链、完整 npm/pnpm 请求、正式 Desktop 的行为及应用窗口均尚未验证；需在初始化许可后再评估成本并实施，不将该能力调查写为完整 HTTPS/GUI 通过。
