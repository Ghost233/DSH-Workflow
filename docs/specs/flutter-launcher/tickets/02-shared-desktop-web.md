[DSH 启动器 Flutter 迁移与 MacLauncher SDK 接入（补录）](https://github.com/Ghost233/DSH-Workflow/issues/1)

## 要构建什么

界面或管理端启动一个认证 Web 入口，连接已有或新打开的官方 Desktop；回收 Web 后 Desktop 与启动器继续运行。

对应父 Spec 用户故事：5、10、11、12、14。针对现有实现核对并补齐此端到端行为；既有测试和 CI 只作为可核对的证据，不自动勾选验收项。

## 验收标准

- [ ] 使用预置的隔离凭据，分别从管理窗口与正式 SDK 启动 Web 访问服务，实际通过稳定端口 33080 完成认证访问。
- [ ] 已有 Desktop 后端时，Web 连接同一运行实例，桌面端和浏览器共享配置、会话、工作区与插件，不新增独立 DSH 业务后端。
- [ ] 缺少可用 Desktop 后端时打开官方桌面端并等待就绪；Web 未真实就绪时不报告 ready=true。
- [ ] 顺序重复启动复用正在运行的 Web 访问资源，不创建重复端口或重复后端。
- [ ] 从界面与 SDK 回收 Web 均释放它拥有的访问资源；启动器仍可管理，Desktop 后端及其业务仍可使用。
- [ ] SDK 声明与真实回调一致：Web 支持启动、回收、状态和日志；Desktop 只支持状态，对其启动、回收和日志请求明确返回不支持。
- [ ] 用真实应用、SDK 与可观察的 Web/后端资源验收，记录候选、固定验证命令和退出证据；声明原生依赖或环境缺失造成的真实失败。

## 新增 Desktop 窗口行为（待验收）

- [ ] 后台启动：未运行时启动并隐藏；已运行时复用且不自动隐藏现有窗口。
- [ ] 启动后显示：未运行时启动并显示/激活，已运行时显示/聚焦同实例；主动打开 DSH 必须显示。
- [ ] 只隐藏窗口，Desktop/Host/Web继续；仅显示已运行窗口时，未运行明确提示且不隐式启动。
- [ ] 在隔离本机 ARM 实际观察冷启动窗口首次显示、晚到显示、隐藏和激活，保持同 Host、Web UI 可用；不以配置或 API 应答替代实际结果，不使用 hidesOthers。

此前共享后端与正常退出证据保留。因用户明确新增窗口功能本票重新打开，新子项未通过；Desktop SDK 仍只声明状态，现有项目原生窗口动作不改变该声明。不扩 server 架构或修改上游。
