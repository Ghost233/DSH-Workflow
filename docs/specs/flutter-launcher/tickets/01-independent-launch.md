## 父项

[DSH 启动器 Flutter 迁移与 MacLauncher SDK 接入（补录）](https://github.com/Ghost233/DSH-Workflow/issues/1)

## 要构建什么

独立打开 Flutter 管理窗口，管理端发现项目与服务并激活窗口；关闭窗口保留业务，重复打开激活既有启动器。

对应父 Spec 用户故事：1、2、3、4、6、9、19、26。针对现有实现核对并补齐此端到端行为；既有测试和 CI 只作为可核对的证据，不自动勾选验收项。

## 验收标准

- [ ] 使用固定的 Flutter、官方 SDK 与工程规范完成独立应用启动；缺少管理端时仍能使用管理窗口和自己的菜单入口。
- [ ] 管理端通过正式 SDK 发现 dsh-workflow 项目、Web 访问服务与 Desktop 后端；应用关联信息能正确打开关联应用。
- [ ] 通过 SDK 打开并激活真实原生管理窗口；关闭窗口后进程继续存活，仍可从自己的入口或 SDK 再次打开。
- [ ] 重复打开应用只激活既有启动器，不创建第二个争用同一数据与访问端口的启动器实例。
- [ ] 管理、插件、日志页面在受支持的最小窗口尺寸下可用，连接失败和操作错误可见。
- [ ] 使用隔离数据完成实际应用启动、正式 SDK 连接和窗口验收；记录候选、固定验证命令、原始退出证据与观察结果，不以业务替身成功代替应用边界证据。
