## 要构建什么

使用者查看插件来源、版本和 DSH 兼容信息，执行单项或批量更新并看到真实安装结果和需重开的提示，通过隔离实例正常重开验证实际加载新版。

对应父 Spec 用户故事：25、26。针对现有实现核对并补齐此端到端行为；既有测试和 CI 只作为可核对的证据，不自动勾选验收项。

## 验收标准

- [ ] 插件页面展示真实来源、当前和最新版本、DSH 兼容信息及状态，未知信息如实表达，较窄窗口下仍可读取和操作。
- [ ] 可更新项支持单项和全部可更新项操作，更新结果与实际受控插件版本一致。
- [ ] 检查或更新失败时呈现原因与已完成部分，不把单项失败或第三方错误描述为全部成功。
- [ ] 插件检查和更新期间不自动终止用户 Desktop 后端；需要重新加载时明确提示完全退出并重新打开 Desktop。
- [ ] 通过隔离下载、安装和实际 package.json 版本核对更新结果，保留需重开提示；正常退出并重开后，核对新 Host/租约和实际加载版本。须取得当前候选原始正常成功，晚到或强制清理不代替通过。
- [ ] 验收采用隔离资源和受控自研插件，遵守第三方源码保持上游原样的维护边界；记录候选、固定验证命令、实际安装版本及原始退出证据；Launcher 自有资源释放仍严格验证，CI 隔离资源清理单独记录。
