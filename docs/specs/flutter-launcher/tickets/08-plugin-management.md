## 要构建什么

使用者查看插件来源、版本和 DSH 兼容信息，执行单项或批量更新并看到真实结果，明确需要自行重开 Desktop 才加载新版；本次验收不操作正在运行的 Desktop。

对应父 Spec 用户故事：25、26。针对现有实现核对并补齐此端到端行为；既有测试和 CI 只作为可核对的证据，不自动勾选验收项。

## 验收标准

- [ ] 插件页面展示真实来源、当前和最新版本、DSH 兼容信息及状态，未知信息如实表达，较窄窗口下仍可读取和操作。
- [ ] 可更新项支持单项和全部可更新项操作，更新结果与实际受控插件版本一致。
- [ ] 检查或更新失败时呈现原因与已完成部分，不把单项失败或第三方错误描述为全部成功。
- [ ] 插件检查和更新期间不自动终止用户 Desktop 后端；需要重新加载时明确提示完全退出并重新打开 Desktop。
- [ ] 通过隔离下载、安装和实际 package.json 版本核对更新结果，保留需要重开 Desktop 才加载的提示。Desktop 正常退出、重开、新 Host/lease 与重开后的实际加载版本硬验收为“用户调整范围后取消/不纳入本次验收”。
- [ ] 验收采用隔离资源和受控自研插件，遵守第三方源码保持上游原样的维护边界；记录候选、固定验证命令、实际安装版本及原始退出证据；Launcher 自有资源释放仍严格验证，CI 隔离资源清理单独记录。

## 用户确认的范围调整（2026-10-07）

用户明确取消 T08 的独立 Desktop 退出、重开、新实例及实际加载版本门槛。保留插件管理 UI、单项/批量/NOOP/失败反馈、隔离真实下载与安装版本，以及需要重开的提示。用户当前 Desktop 正在运行任务，本机验收不得启动、停止、重启或修改其 Host、业务进程或当前插件目录；实际安装场景仅使用 GitHub Actions 的明确临时隔离资源。此前完整 T08 成功仅保留为历史证据，不将取消项写成新范围 PASS，也不自动重开正式 T08 工单。
