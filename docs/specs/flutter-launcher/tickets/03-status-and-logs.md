## 要构建什么

使用者通过管理端和日志页面判断真实运行、就绪与实例范围，后端健康查询失败或 Web 换实例时仍得到可信信息。

对应父 Spec 用户故事：15、16、26。针对现有实现核对并补齐此端到端行为；既有测试和 CI 只作为可核对的证据，不自动勾选验收项。

## 验收标准

- [ ] SDK 状态与实际 Web 资源一致；监督进程仍活着但 Web 已断开时不将其误报为正在运行。
- [ ] Web 运行身份来自真实业务连接，SDK 会话更换不伪造新业务实例，未知实例信息保持未知。
- [ ] Desktop 状态使用可信后端运行记录和就绪观测；进程已确认存活但健康查询不可用时，保留运行事实并表达就绪信息不足。
- [ ] SDK 日志与管理窗口呈现原始日志文本；未提供的写入时间、流类型保持未知，批次观测时间不冒充写入时间。
- [ ] Web 重连或重启后日志按实际实例隔离，前一实例日志不被标成新实例内容。
- [ ] 覆盖完整返回、限量读取和缓存确实丢弃内容的截断场景；恰好等于读取上限而未丢失内容时不误报截断。
- [ ] 覆盖启动、运行、停止、后端健康不可用和日志换实例等应用边界场景，绑定候选、固定验证命令与原始证据；敏感访问凭据不出现在 SDK 状态、日志或声明中。
