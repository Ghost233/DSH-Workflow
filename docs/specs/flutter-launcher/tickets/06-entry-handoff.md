## 要构建什么

管理端成功接管后隐藏重复菜单，仍可打开管理窗口；管理端退出、断线或迟到动作后自己的入口恢复，业务继续运行。

对应父 Spec 用户故事：6、7、8、9。针对现有实现核对并补齐此端到端行为；既有测试和 CI 只作为可核对的证据，不自动勾选验收项。

## 验收标准

- [ ] 入口接管的成功应答对应真实原生菜单入口已经隐藏；拒绝或失败时自己的入口保持可用，不虚报接管成功。
- [ ] 入口接管后仍能通过正式 SDK 打开并激活真实管理窗口，关闭窗口后业务保持运行。
- [ ] 管理端退出、连接断开或接管未完成时，原生菜单入口实际恢复；Web 和 Desktop 后端的运行实例及访问能力保持。
- [ ] 接管动作在断线后迟到完成，以及断线后重新连接时，不会让已经失去有效接管的应用永久隐藏入口。
- [ ] 入口归还与服务回收分开处理，管理端重新连接后可以再次正常协作入口与窗口。
- [ ] 在隔离环境中使用实际应用、正式 SDK 和原生可见性验证，记录候选、固定验证命令、退出证据和业务继续运行的证据，不以原生桥替身应答代替。
