## 要构建什么

使用者迁移后继续使用原有配置和密码，并能通过管理窗口更改认证、局域网设置与工具权限，按提示在实际业务中生效。

对应父 Spec 用户故事：20、21、22。针对现有实现核对并补齐此端到端行为；既有测试和 CI 只作为可核对的证据，不自动勾选验收项。

## 验收标准

- [ ] 用隔离的迁移前数据验证应用身份、数据位置、偏好键、内网密码及旧钥匙串只读迁移兼容，原有配置和历史数据不丢失。
- [ ] 管理窗口设置与修改内网密码后，认证 Web 访问使用正确密码；错误或无效输入可见，密码按既有受限存储规则保存。
- [ ] 密码变更按当前应用生命周期作用到实际 Web 访问；SDK 声明、状态与日志不读取或传递内网密码。
- [ ] 局域网设置保持既有认证与设置修改边界，管理窗口明确其生效时机；按提示重连 Web 后，允许与禁止的客户端行为符合所选设置。
- [ ] 完整访问权限设置保存并呈现真实选择，通过实际持久化证据核对保存结果，界面明确需要重新打开 Desktop。独立 Desktop 正常退出、权限重开和新 Desktop 实际采用权限不纳入本次验收。
- [ ] 设置操作或持久化失败如实呈现，不把失败显示成已保存，也不自动关闭用户正在使用的 Desktop 后端。
- [ ] 用隔离凭据、配置和实际业务请求记录迁移及更改前后的候选、固定验证命令与原始证据，不对用户当前配置做验收性写入。

- [ ] 按当前范围取得完整设置命令退出 0，并核对 Launcher 自身、owned Web、SDK 连接及客户端、日志等自有资源释放；独立 Desktop 可以仍运行，隔离 CI 清理结果另行记录。
