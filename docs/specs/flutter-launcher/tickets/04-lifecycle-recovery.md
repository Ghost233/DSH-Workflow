## 要构建什么

Desktop 失联后恢复 Web，界面与 SDK 冲突操作得到一致结果，启动中或重复退出仍清理全部自有 Web 资源。

对应父 Spec 用户故事：5、13、17、18。针对现有实现核对并补齐此端到端行为；既有测试和 CI 只作为可核对的证据，不自动勾选验收项。

## 验收标准

- [ ] Desktop 退出或运行实例改变后，可以从管理窗口或 SDK 重新建立 Web 连接；监督进程存活时仍能恢复连接，且不重复占用访问端口。
- [ ] 界面与 SDK 共用真实的启动、回收和重连互斥边界；跨 SDK 重连保持同一业务操作的互斥。
- [ ] 复现界面启动尚未取得进程句柄时的 SDK 回收冲突，得到准确的忙碌或结算结果，不返回回收成功后又出现正在运行的 Web。
- [ ] 并发和重复请求不产生多份 Web 资源或第二个 Desktop 后端，操作结果与最终资源状态一致。
- [ ] 正常退出、重复退出与启动未完成时退出均等待同一清理过程，待产生的受控进程也必须结算。
- [ ] 受控 Web 子进程暂停或不响应正常终止时，退出完成后该进程和访问端口实际释放；Desktop 后端继续保持独立生命周期。
- [ ] 用真实进程与应用/SDK 操作进行故障场景验收，冻结并记录候选、验证命令、退出结果与资源观察证据；保持用户当前服务和数据。
