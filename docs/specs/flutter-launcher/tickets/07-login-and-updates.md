## 要构建什么

使用者管理系统登录项并看到实际批准状态，检查适用的稳定发行版本并打开本项目发行页面。

对应父 Spec 用户故事：23、24。针对现有实现核对并补齐此端到端行为；既有测试和 CI 只作为可核对的证据，不自动勾选验收项。

## 验收标准

- [ ] 管理窗口的登录启动选择与 macOS 实际注册、取消注册结果一致，准确呈现未注册、已启用及需要系统批准等状态。
- [ ] 系统拒绝或不支持时显示真实结果，不虚报已启用；系统批准场景记录所用隔离环境与实际观察，不替用户授予权限。
- [ ] 更新查询仅选择本项目适用且比已安装版本新的稳定 macos-v 发行，排除草稿、预发布、无效或不匹配标签。
- [ ] 覆盖数字主版本/次版本排序、无更新、空列表和请求失败；管理窗口结果与发行响应及已安装版本一致。
- [ ] 发现更新后打开正确的本项目发行页面，操作不会自动下载替换当前应用或将 main 构建产物冒充正式发行。
- [ ] 在独立应用管理窗口与实际原生登录项边界验收，冻结并记录候选、验证命令与执行证据；使用受控发行响应补充边界场景。

## 新增登录启动窗口规则（待验收）

- [ ] 登录启动遵循已保存的“启动时隐藏窗口”，缺值默认 false，与常规启动一致。
- [ ] 已运行 Desktop 保留原窗口状态，登录/自动启动不能隐藏使用者正在用的窗口；主动打开 DSH 仍显示/聚焦。
- [ ] 本地先验证现有启动路线和偏好分支，系统登录项的干净 runner 边界留稳定候选最终远程；不自动替使用者变更已有服务。

因用户新增启动可见性，本票重新打开。此前登录项/稳定版更新成功保持历史，更新功能不扩展或重复修补。
