# Station 审批通知

审批通知与查询共用已配对的 Dot MCP 入口，但配对不等于订阅。新版在全局配对入口公布 `dsh.approval.pending`，无需选择单个 DSH 会话。

1. 启动 Station Web 后端并检查已配对的 MCP 连接。发现能力应包含 `events`，事件列表应包含 `dsh.approval.pending`。
2. 由 ChatGPT 发起订阅。默认仅接受 OpenAI 订阅服务提供的官方 HTTPS 回调路径；不需手填地址或密钥。Station 校验回调域名、公网地址和 TLS，再通过签名挑战确认接收端。回调验证预算最多 10 秒。
3. 在隔离 DSH 会话触发真实待审批，先不要批准或拒绝。用同一事件 ID 核对 Station 发送与 Dot 收件。不传请求正文、命令、签名密钥或原始会话 ID，也不代替用户审批。

只有 DSH 已记下一次审批请求且同会话确实有审批在客户端网关等候时才发送。已经解决或快速自动拒绝的请求不通知。未投递的短期队列不跨重启，不补报历史审批；订阅凭据以绑定当前配对的加密格式在本机存储。事件模块不可用时，独立的只读查询仍可用。

如需经明确批准的固定接收端，可在 Station 私有回执目录配置 `station-dot-approval-receiver.json`，权限 0600。内容为 `{"url":"<完整 HTTPS 回调地址>","address":"<已核验的公网 IPv4>"}`。不要提交文件或在聊天中粘贴回调地址或签名密钥。
