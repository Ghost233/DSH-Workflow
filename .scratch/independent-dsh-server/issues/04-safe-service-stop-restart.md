# 04 — 检查未完成工作并安全停止或重启服务

**要构建什么：** 用户从管理入口停止或重启 DSH 服务前，看到运行中的代理、待处理工作和定时提醒。有影响或状态未知时先确认，取消后业务保持运行。手动重启后继续读取原有配置和历史。对应规格用户故事 13、14、15、22、26。

**被什么阻塞：** 01 — 从启动器和 SDK 启动并观察独立 DSH 服务。

**状态：** ready-for-agent

- [ ] 启动器和正式 SDK 的服务控制能力与实际操作一致，能够请求停止和重启独立服务。
- [ ] 停止或重启前检查运行代理、待处理消息、后台任务和相关定时提醒；检查失败或超时明确作为未知状态处理。
- [ ] 有未完成工作或状态未知时，启动器展示影响并要求明确确认；SDK 未取得必要确认时返回可理解的原因，不静默停止。
- [ ] 用户取消后实例、任务和服务访问保持运行，停止检查不会留下锁定状态。
- [ ] 检查后新接收的任务不能绕过确认；确认仅对当前操作和当前实例有效。
- [ ] 确认停止后真实服务退出；手动重启产生新运行实例，并读取同一套既有配置和历史。
- [ ] 验收使用真实任务与服务进程，分别覆盖空闲、活动、未知、取消和并发变化；强制清理不算正常停止通过。
